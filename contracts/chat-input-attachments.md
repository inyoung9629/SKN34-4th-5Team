# Chat input attachments (v2)

Existing text-only POST/PUT and SSE frames stay unchanged. New options are v2-only; v1 rejects nonempty new options with 400.

## Ownership and routes

All private routes use existing member JWT or guest identity and `get_owned_session`. Missing/foreign sessions or IDs return 404; no public storage keys/URLs. Frontend application auth uses JWT, not new authentication cookies.

- `GET /api/v2/chat/tool-groups/`: public `{id,label}[]`; manual groups union automatic capabilities only after JEV PASS.
- `GET /api/v2/chat/sessions/{session_id}/attachments/`: persisted metadata, including legacy URL references.
- `POST /api/v2/chat/sessions/{session_id}/attachments/`: multipart `file` exactly once; returns 201. Content-Length required (411), oversized body 413. JSON `{url}` registers owned URL metadata with **201**, without DNS, HTTP extraction, file upload or cached source bodies; duplicate normalized URLs reuse an existing session reference.
- `GET /api/v2/chat/sessions/{session_id}/attachments/{attachment_id}/`: owned private file bytes with `Cache-Control: private, no-store` and `nosniff`; URL references return 404.
- `DELETE /api/v2/chat/sessions/{session_id}/attachments/{attachment_id}/`: unused reference 204, current or historical checkpoint reference 409. Message-window eviction never deletes storage/history/checkpoints.

Metadata: `{id:UUID,kind:"image"|"text"|"url",name,content_type,size,width,height,url,created_at}`. URL is legacy source URL or private file API path. Never expose extracted text, object keys, embeddings or provider details.

## Message and composer

Required nonblank `content` <=2200 chars, existing `context` and PUT `message_id` unchanged. Optional `tool_group_ids:string[]` (known distinct IDs), `attachment_ids:UUID[]` (first-occurrence deduplicated, owned by conversation). POST omissions mean empty; PUT omissions preserve existing references, explicit arrays replace them. Ten combined unique references per submitted question; images/TXT/MD may fill all ten. URL references retain their separate maximum of three and supply URL strings only, never cached bodies.

Composer reserves the entire file batch synchronously before any upload. Pending/ready/failed/cancelled cards consume slots; invalid/eleven-reference batches reject atomically, retaining existing draft/cards. Retry reuses reservation/IDs. Session upload count has no lifetime cap. Each text file <=2MiB UTF-8 TXT/MD; images <=10MiB static JPEG/PNG/WebP, <=20 million pixels, <=10000px each dimension. MIME mismatches, binary/executable text, SVG and animation are rejected.

**Inline input references**: shared popup/workspace editors register complete public HTTP(S) URL tokens at paste/typing/blur/send boundaries; IME composition waits. URLs remain atomic inline chips with their original literal text, address disclosure, removal and failed/cancelled retry; there is no manual URL dialog. A single plain-text paste of at least 2000 Unicode codepoints becomes a numbered TXT inline reference, not accumulated typing; registration failure restores the original paste and surrounding draft text. Photos and manually selected TXT/MD remain preview cards. Tool selection through + or bare @ inserts the same idempotent inline marker; x, Backspace, Delete and Undo/Redo reconcile marker-owned capabilities while preserving independently selected groups. Saved-question edits rehydrate marker ownership. Removed pending references retain their terminal completion for Undo; deleting a conversation purges only its draft/edit reference history and fences late session/upload callbacks. URL-only ready attachments send their original literal URLs as the nonblank question fallback. Pending references reserve slots atomically and sends wait for the selected upload batch, rejecting if newer input owns the draft. Removal suppresses boundary reconversion until URL text leaves the draft or a renewed paste occurs. Repeated normalized URLs deduplicate within the draft and server session; fragments drop from reference identity, queries remain. Existing URL cards/history/cached records survive edits/retries/reload and contribute at most their URL string, never cached/extracted body. Public metadata validation rejects credentials, private literal/local/internal/root-dotted hosts, malformed names and nonstandard ports without DNS. No iframe work or cached-record deletion. Late successful registration after removal attempts owned unused-metadata cleanup; server historical-reference 409 protection remains. Unknown outcomes after abort cannot be reconciled without a registration response; no global cleanup of preserved historical metadata occurs.

## Actual model-visible rolling window

V2 previously had no model-history token/window trimming (JEV's own classifier history bound is separate). `recent_messages` now retains **current HumanMessage group + three previous HumanMessage groups**, maximum four conversational turns. Slicing happens only at a HumanMessage boundary, retaining complete AI/tool-call/result exchanges. `_stream_turn` applies it after completed-turn public-history projection and before graph invocation. Attachment middleware applies the same bound to direct graph callers and model calls; intra-run tool messages remain attached to the current turn. Full stored checkpoint/public history is unchanged.

Within those four turns, attachments are restored only into their corresponding **HumanMessage**, never all-session system injection. Process groups newest-first; restore a repeated source only at its latest reference. TXT/MD bodies remain complete with original name, ID, full `chars 0:length` and unpredictable per-request untrusted-data delimiters; no embeddings, semantic selection, top-k, truncation or source-tail drop. Sources and metadata are explicitly data, never instructions.

Combined retained source body budget: **2MiB UTF-8**. Combined retained assembled attachment block budget: **20,000 cl100k_base tokens**, counting each group's headers, metadata, separators, instructions and delimiters, treating special-token-looking strings as ordinary text. Current-turn sources must fit in full or produce explicit AttachmentProcessingLimit/DirectContextLimit before the main model call (existing SSE error and persisted failed state). Older turns are admitted newest-first while both aggregate budgets fit; at first overflow that whole older HumanMessage group and every older group roll out together. A valid new turn is not rejected because cumulative historical attachment text is large. This is an attachment-only token budget, not a bound on all tool output or the entire model request.

Images: current ten images remain visible; fill remaining image capacity from the latest historical references up to **ten unique images total**, restoring each ID once at its latest retained question. Old image references beyond the image budget are not read. Turns outside the four-turn window have no ownership/source queries or tokenization; after budget overflow no still-older sources are fetched. At most four groups / forty submitted references are considered (each message is capped at ten). Legacy URLs are ownership-checked; URL strings may be placed in the corresponding question, but cached extracted bodies are never read/fetched/injected.

JEV scope classification runs on text/history/context before restoration, and no sources are read on refusal. Images do not themselves establish scope. Cancellation is checked before/after each text read, assembly and image restoration; already-in-flight work must return first. Storage outbox maintenance and auth/private media safety remain unchanged.

## Native web search (latest coordinator authorization)

The existing main GPT Responses model receives `{type:"web_search"}` only for JEV PASS current questions that contain an HTTP(S) URL and a reading/summary/explanation/check request, URL-only input, or a current URL attachment reference. Explicit reference follow-ups may use retained URL strings within the same four-turn window; unrelated follow-ups or evicted references do not permanently enable the tool. An incidental homepage hyperlink alone does not enable search. TXT/MD source content cannot grant this capability. The first main model call uses specific `tool_choice:{type:"web_search"}` so search is not optional; later rounds use auto and retain the existing domain function allowlist. Specialists receive no native search tool. Existing final-call budget still removes all tools.

No extra model, summarizer, HTTP extractor or paid verification call. Existing gpt-6-luna, medium reasoning, Responses setting, credentials and endpoint remain unchanged. Installed langchain-openai 1.6.6 / openai 3.19.2 serialize the native tool; inspected configured base host was api.openai.com. No runtime global provider/model switch or HTTP fallback. Private literal IPs, credentials, local/internal names and nonstandard ports reject before provider invocation. No local DNS/page fetch; provider performs remote search, and it is not a guarantee of full-body access or opening every supplied URL. Blocked/login/unsupported pages must be reported as unverified, not invented.

Responses URL citation annotations are projected to visible clickable Markdown source links in streamed deltas and persisted final answer, deduplicated and restricted to credential-free HTTP(S). Existing token usage callbacks, unknown-usage handling, failure settlement and cancellation ownership remain in use. Built-in web-search tool fees are separate provider charges and are **not** newly priced by this token-based credit ledger. Native provider/model acceptance and actual search coverage were not exercised live; provider errors remain explicit existing SSE failed-turn errors. Official reference: https://developers.openai.com/api/docs/guides/tools-web-search
