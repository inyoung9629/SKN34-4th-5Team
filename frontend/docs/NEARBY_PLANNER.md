# 구장 주변에서 직접 만드는 코스

`/routes/new`에서 구장 선택 → 카테고리/지도 탐색 → 장소 상세 또는 빈 지도 클릭 → 코스 추가 → 방문 순서 변경 → 코스 완성 → 이름 입력 → 코스 저장 순서로 이용합니다. 본문은 선택 사항이며 저장 범위는 현재 브라우저입니다. 챗봇 호출 없이 동작합니다.

## 지도 연결

`frontend/.env.example`을 참고해 `frontend/.env.local`에 `NEXT_PUBLIC_KAKAO_MAP_KEY`를 설정합니다. Kakao Developers의 **JavaScript 키**이며 SDK 도메인에 `http://localhost:3000` 및 실제 배포 주소를 등록해야 합니다. 환경변수 변경 후 서버를 재시작합니다. 장소 검색은 브라우저가 `POST /api/v1/places/search/`로 Django에 직접 요청하며, REST 키와 검색 결과 저장은 백엔드가 담당합니다.

2026-09-11 로컬 브라우저에서 실제 지도·장소 검색과 9개 구장 전환을 확인했습니다.

### 관광공사 장소 연결

루트 backend 환경에 서버 전용 `TOUR_API_KEY`를 설정합니다. 브라우저는 `GET /api/v1/tourism/?stadium=JAMSIL&lat=…&lng=…`를 호출하며 Nginx가 Django `/tourism/`으로 전달합니다. Next route와 캐시는 없고 키는 backend 요청에만 사용합니다.

- 카카오에서 확인한 실제 구장 중심과 반경 2,500m로 관광지(12), 문화시설(14), 레포츠(28)를 조회합니다. 유형별 100건 × 최대 3페이지, 거리순이며 좌표로 거리를 다시 검사합니다. 레포츠는 산책·실내 활동으로 분류되는 장소만 반영합니다.
- 장소 이름과 제공된 분류 코드로 산책·관광 명소·실내 놀거리에 연결합니다. 야외 시설을 모두 실내로 취급하지 않으며, 연도와 축제/페어 등이 명시된 행사는 상설 장소에서 제외합니다. 음식점·숙박·행사 일정·사진은 이번 관광공사 연동 범위에 포함하지 않습니다.
- 목록의 ‘관광공사’ 표시로 출처를 확인합니다. 관광공사만 보기 필터는 제거했으며 두 출처를 함께 표시합니다. 두 서비스의 이름을 정규화해 비교하고 위치가 80m 이내이거나 같은 도로명 건물 주소이면서 250m 이내인 장소만 합칩니다. 같은 건물의 이름이 다른 시설은 합치지 않습니다. 명칭·좌표 차이로 일부 중복이 남을 수 있습니다.
- 합친 장소는 카카오 ID와 `tourContentId`를 함께 보존합니다. 관광공사 전용 ID는 `tour:콘텐츠ID`로 구분하여 서로 다른 서비스의 숫자 ID가 충돌하지 않게 합니다. 조회 도중 장소를 담거나 저장 후 수정해도 같은 관광공사 장소의 중복 추가를 막습니다.
- 관광공사 전용 장소의 외부 링크는 카카오맵에 해당 좌표를 표시합니다. 카카오 장소 상세 ID를 임의로 만들지 않습니다.
- Django는 요청마다 공급자를 조회하고 provider metadata만 `EXTERNAL_DATA_SYNC_INTERVAL_SECONDS` 정책으로 조건부 저장합니다. 알려진 구장 코드와 기존 좌표에서 1km 이내의 중심 좌표만 허용합니다.
- 일부 실패 시 성공한 결과를 표시하고 관광공사만 다시 조회할 수 있습니다. 키 미설정·관광공사 실패가 카카오 장소 검색을 막지 않습니다.

공식 서비스: [한국관광공사 국문 관광정보](https://www.data.go.kr/data/15101578/openapi.do).

## 조회와 표시 기준

카테고리는 다중 선택입니다. 처음에는 전체와 모든 개별 항목이 선택되고, 항목을 누르면 해당 분류만 켜거나 끕니다. 모든 항목이 켜진 경우에만 전체가 선택 상태이며, 전체를 누르면 모두 선택된 상태에서는 모두 끄고, 그 외에는 모두 켜면서 소분류 제한도 초기화합니다. 전부 끄면 주변 장소가 0곳으로 표시됩니다. 각 대분류 옆 화살표를 누르면 조회된 장소의 소분류를 여러 개 선택할 수 있습니다. 선택한 소분류는 펼침 메뉴의 체크박스로만 확인하며 그 분류에만 필터를 적용합니다. 소분류를 선택하면 대분류도 켜집니다. 선택이 없으면 해당 대분류 전체를 표시합니다.

숙박은 카카오 업종 경로의 숙박 바로 아래 분류(호텔, 여관·모텔, 게스트하우스 등)를 표시합니다. 세부 업종이 없는 숙박은 기존 ‘숙박’을 유지하며 이름에 ‘호텔’이 있어도 업종을 추정하지 않습니다. 먹거리는 기존 음식 종류를 소분류로 사용하며, 카페·디저트도 업종 경로의 카페 유형과 제과·디저트 유형을 소분류로 표시합니다.

실내 놀거리의 목록과 선택한 장소 카드에는 세부 분류를 표시합니다. 카카오는 업종 경로에서 시설·활동 분류(볼링, 보드카페, 방탈출카페, 미술관, 전시관 등)를 사용하고, 브랜드 하위 경로보다 시설 분류를 우선합니다. 관광공사는 `categoryCode2`에서 확인한 문화시설 `cat3` 명칭을 사용합니다. 분류가 부족하면 장소명에 명시된 활동을 사용하며, 판단할 수 없으면 기존 큰 분류를 유지합니다. 카카오 관광명소 경로에 속한 실내 장소는 앞서 선택한 첫 번째 관광 분류 표시를 유지합니다. 조회 대상과 핀의 큰 카테고리는 바꾸지 않습니다.

### 카카오 관광명소 세부 분류 선택

카카오 `AT4` 결과 및 `여행 > 관광,명소` 경로의 장소는 첫 번째 세부 분류가 **도보여행, 동물원, 문화유적, 수목원, 식물원, 수목원·식물원(실제 값 `수목원,식물원`), 저수지, 전망대, 천문대, 테마거리, 테마파크, 호수**인 경우에만 유지합니다. `AT4`로 반환되는 `스포츠,레저` 경로도 유지합니다. 각 분류의 모든 하위 분류를 포함하며, 이름에 따른 추가 제외 규칙은 적용하지 않습니다. 따라서 도보여행의 인증대, 테마거리의 골목형상점가, 테마파크의 워터테마파크도 선택한 분류에 따라 남습니다.

오른쪽 주변 장소 목록에서는 `subcategory`로 첫 번째 세부 분류를 표시합니다. 예: `도보여행 > 둘레길 > 인천둘레길` → **도보여행**, `동물원 > 실내동물원` → **동물원**, `스포츠,레저 > 스포츠시설 > 눈썰매장` → **스포츠,레저**. 지도 핀·탭의 큰 카테고리와 저장 코스 형식은 유지합니다. 이 규칙은 카카오 관광명소에 적용하며, 다른 업종 검색과 관광공사 자체 분류는 기존 기준을 사용합니다. 두 출처를 합친 장소의 목록은 카카오 세부 분류를 사용합니다.

- 기존 좌표는 주소 지오코딩 결과이므로 종합운동장 전체를 가리킬 수 있습니다. 먼저 구장명을 정확도순으로 검색하고 야구장 업종과 명칭이 맞는 장소를 확인합니다. 그 좌표를 반경의 중심으로 사용합니다.
- 이후 카카오 검색은 구장 중심, 반경 2,500m, 거리순, 페이지당 15건으로 요청합니다. 각 검색 조건은 최대 3페이지를 읽습니다. 응답 좌표로 거리를 다시 계산하고 반경 밖·잘못된 좌표를 제거합니다.
- 먹거리·카페·산책·관광·실내 놀거리를 먼저, 편의점을 다음, 숙박을 마지막에 조회합니다. 사용자가 특정 카테고리를 누르면 대기 중인 해당 검색이 먼저 실행됩니다.
- 음식점/카페/관광/문화시설/편의점/숙박의 카테고리 검색과 음식 종류·공원·산책로·둘레길·볼링장·보드게임카페·방탈출·영화관 키워드 검색을 병행합니다. `category_name`으로 분류하며 상세 메뉴나 영업 여부를 추정하지 않습니다.
- Kakao 장소 ID로 중복을 제거합니다. 선택한 카테고리 수와 관계없이 조회된 해당 장소를 모두 표시합니다. 검색창은 **이미 조회된 장소**의 이름·업종을 검색합니다.

지도 표시에는 별도의 카테고리별 개수 상한이 없습니다. 각 검색 조건은 백엔드 장소 API에서 최대 15건 × 3페이지를 조회하고, 중복 제거·반경·시설 제외·선택한 분류 조건을 통과한 결과를 모두 표시합니다. 서로 다른 검색 결과를 합치므로 총수는 45곳을 넘을 수 있습니다. 이는 반경 안의 모든 업소를 수집한다는 뜻은 아닙니다.

현재 화면에서 다른 장소와 40px 미만으로 가까이 모인 장소만 실제 좌표에 카테고리 색상의 작은 원으로 표시합니다. 떨어져 있는 장소는 축소 상태에서도 기존 아이콘을 표시합니다. 숫자 묶음은 표시하지 않습니다. 작은 원의 클릭 영역은 24px이며, 누르면 장소 상세가 열립니다. 확대·이동할 때 화면상 간격을 다시 계산하며, 간격이 충분히 벌어진 장소나 선택한 장소는 기존 카테고리 아이콘을 표시합니다. 코스에 담은 장소는 방문 순서 번호를 유지합니다. 선택 장소는 최대 12곳이며 중복 추가를 막습니다. 번호는 방문 순서이며 이동 경로는 선택한 이동 수단의 실제 API 응답으로 표시합니다. 내 코스에서 출발지와 이동 수단, 구간별 예상 시간을 확인합니다.

## 구장 밖 시설 판정의 한계

Kakao 검색 응답에는 구장 내부 여부가 없습니다. 구장과 같은 도로명 건물 주소, 야구장 업종, 내부 지점으로 보이는 명칭, 구장 중심 80m 이내 여부로 보수적으로 제외합니다. 같은 주소를 공유하는 외부 시설이 빠지거나 주소가 잘못 등록된 내부 시설이 남을 수 있습니다. 정확한 경계 판정이 필요하면 검증된 구장 부지 폴리곤과 예외 장소 ID를 추가해야 합니다. 기존 CSV의 `in_stadium_flag`도 60m 거리 기반 값이므로 검증된 정답으로 사용하지 않습니다.

검색 결과 상한 때문에 반경 내 모든 업소를 보장하지 않습니다. 이 제한은 화면의 ‘장소 표시 기준’과 장소 상세에도 안내합니다.

## 코드와 오류 처리

- `components/nearby-route-planner.tsx`: 지도, 핀, 필터, 상세 카드, 코스 목록.
- `lib/nearby-places.ts`: 카테고리, 분류, 거리/내부 시설 필터, 중복 제거, 표시 한도, 순서 변경, 묶음 계산.
- `lib/nearby-search.ts`: Django 장소 검색, 구장 위치 확인, 우선순위 큐, 페이지 처리. 브라우저 캐시는 없습니다.
- `lib/tour-api.ts`, `lib/tour-places.ts`: Django 관광 API 클라이언트와 브라우저 응답 검증·거리 필터·업종 분류.
- 구장 변경/화면 이탈 시 대기 중인 작업을 중단하고 늦게 도착한 응답을 무시합니다. 구장 변경 전 이미 고른 장소가 있으면 비울지 확인합니다. 부분 실패 시 성공한 결과를 유지하고 실패한 검색을 재시도할 수 있습니다.
- `lib/routes.ts`: 코스의 장소 ID·이름·주소·좌표·카테고리와 순서를 기존 로컬 저장 형식에 추가합니다. 기존 코스도 열 수 있습니다. 서버 공개 저장은 기존과 동일하게 미연결입니다.

공식 SDK: [장소 검색 문서](https://apis.map.kakao.com/web/documentation/#services_Places), [시작 안내](https://apis.map.kakao.com/web/guide/).

단위 테스트는 반경 경계, 내부 시설 제외, 업종 분류, 표시 우선순위, 중복 제거, 순서 변경, 묶음 계산, 페이지 제한, 부분 실패, 중단된 요청, 구장 위치/명칭 해석을 확인합니다. 실제 브라우저에서는 지도 핀/목록 선택, 추가·삭제·순서 변경, 중식 필터, 편의점 제한, 저장·수정과 360/768/1440px 배치를 확인합니다.

관광공사 테스트는 반경/내부 시설 제외, 출처 ID 충돌 방지, 두 서비스의 도착 순서와 재조회에 따른 중복 통합, 같은 건물의 별개 시설 보존, 응답/업무 오류, 인증키 인코딩, 최대 페이지와 부분 실패를 확인합니다. 2026-09-11 전체 181개 테스트와 빌드·ESLint를 통과했고, 실제 9개 구장 서버 조회와 브라우저의 관광공사 장소 저장·수정·구장 전환·빈 결과·화면 크기를 검증했습니다. 잠실 기준 아시아공원, 코엑스 아쿠아리움, 별마당도서관 등을 포함한 21곳이 반영됐습니다. 결과 수와 분류는 제공 데이터 갱신에 따라 달라질 수 있습니다.

밀집 장소의 원형 점은 14px이며 클릭 영역은 24px입니다. 카테고리별 소분류 필터에 맞는 조회 결과를 모두 표시합니다.

대분류는 132px 동일 폭으로 줄바꿈 배치하며 전체 버튼은 64px, 버튼 높이는 40px입니다. 화살표는 중앙 정렬한 SVG이고, 소분류 태그와 별도의 하단 예약 공간은 표시하지 않습니다.

병원·약국 카테고리를 제거하고 HP8/PM9 검색 요청을 중단했습니다. 다른 검색에서 해당 그룹이 반환되어도 제외합니다. 편의점 검색의 API 결과 한도는 유지되지만 별도의 지도 표시 한도는 없습니다.

실제 도보·자동차·대중교통 경로와 시작 위치 지정은 [코스 이동 안내](COURSE_DIRECTIONS.md)를 참고합니다.
