# 코스 경로와 예상 이동 시간

코스 작성 화면의 ‘내 코스’와 저장된 코스 상세 지도에서 사용합니다. 작성 화면은 ‘코스 완성’을 한 번 누른 뒤부터 경로와 예상 시간을 조회합니다. 처음 비어 있는 ‘내 코스’에도 ‘시작 위치 설정’을 표시하며 코스 첫 지점·내 위치·지도에서 직접 지정 중 선택할 수 있습니다. 기본 이동 수단은 도보이고 자동차·대중교통은 선택할 때만 조회합니다. 완성 후에는 출발지 선택 자리에 코스 이름 입력과 코스 저장 버튼을 표시합니다. 이름과 방문 장소만으로 저장할 수 있으며 본문은 선택 사항입니다. 방문 순서는 사용자가 정한 순서이며 최적화하거나 재배열하지 않습니다.

- 지도에서 직접 지정을 누르면 지도로 이동해 안내를 표시합니다. 지도를 클릭하면 출발 핀을 찍고 선택한 출발지 → 코스 1번 구간을 추가합니다. 지정 취소와 재지정을 지원하며 출발 핀은 저장 코스의 방문 장소를 바꾸지 않습니다.
- 내 위치 출발을 누르면 브라우저 위치 권한을 요청합니다. 현재 위치 → 코스 1번 구간을 추가하며, GPS는 지속 추적하지 않습니다. 위치 거부·시간 초과 시 안내하고 코스 1번 출발로 돌아갈 수 있습니다.
- 장소 추가·삭제·순서 변경·이동 수단 변경 시 450ms 후 재조회하고 이전 요청을 중단합니다. 이전 코스 응답은 현재 코스에 표시하지 않습니다.
- 도보·자동차·대중교통 모두 실제 API 경로 좌표를 지도에 표시합니다. 직선거리로 시간을 추정하지 않습니다. 구간별 안내를 펼쳐 이동 안내를 확인할 수 있습니다.
- 총 시간은 구간별 초 단위를 합산한 뒤 분으로 올림합니다. 개별 구간도 올림하므로 화면상 분 단위 합과 소폭 다를 수 있습니다. 식사·관람 등 체류 시간과 주차 시간은 포함하지 않습니다.
- 대중교통은 각 구간에서 제공된 경로 중 시간이 가장 짧은 경로를 사용합니다. 각 구간을 현재 조건으로 조회해 합산하므로 미래 출발 시각에 맞춘 연결 여정이나 환승 보장이 아닙니다.
- 조회 실패 구간에는 오류를 표시하고 전체 시간·거리 합계를 표시하지 않습니다. 성공 구간의 경로만 표시하며 실패 구간을 임의 직선으로 잇지 않습니다.

## 지도에서 장소와 지점을 함께 추가

- 작성 지도는 처음부터 코스 편집 상태입니다. 별도의 직접 그리기/그리기 완료 버튼은 없습니다. 빈 지도를 클릭하면 직접 지정한 지점, 매장 핀을 클릭하면 정보 카드만 열립니다. 카드의 코스에 담기를 누르면 이름·주소·장소 ID가 있는 방문 장소가 같은 코스에 추가됩니다.
- 매장 핀 위에 마우스를 1초 동안 올리면 상세 카드가 열립니다. 핀 클릭과 키보드 포커스로도 정보를 확인할 수 있습니다. 이름만 나오는 기본 툴팁은 사용하지 않습니다. 카드에서도 코스에 추가할 수 있으며 이미 담은 장소는 중복 추가하지 않습니다.
- 빈 코스의 첫 지점은 출발, 이후는 1·2·3으로 표시합니다. 매장을 출발지로 선택해도 매장 이름을 유지합니다. 기존 코스에는 뒤에 이어서 추가합니다.
- 지도 우클릭과 핀 위 우클릭은 가장 최근에 추가한 매장 또는 자유 지점 하나만 삭제합니다. 목록에서 순서를 바꾸거나 중간 지점을 삭제해도 현재 편집 중 생성 순서대로 되돌립니다. 초기화 버튼은 모든 방문 지점과 별도 출발지를 비우고 출발지 선택 화면으로 돌아갑니다.
- 코스 핀은 끝이 뾰족한 모양이며, 빈 지점 지정 시 화살표·드래그 중 잡는 손 커서를 사용합니다. 시작 위치를 별도로 지정하는 동안에는 코스 지점 추가를 잠시 중지합니다.
- 자유 지점은 `isMapPoint`, 매장 선택은 `isDrawnPoint`로 코스에 저장됩니다. 이름과 ID를 보존하며 상세 지도에서도 번호·핀·경로를 표시합니다. 최대 12개 지점, 실제 경로 및 예상 시간 자동 갱신은 기존과 같습니다.

## 서버 연결

백엔드 Django 설정의 `KAKAO_REST_API_KEY`를 사용합니다. 브라우저 공개 환경변수나 Next 컨테이너에는 이 키가 필요하지 않습니다.

브라우저는 `POST /api/v1/travel/directions/`에 이동 수단과 좌표만 전송하고, 일반 Nginx `/api/v1/` 경로가 접두어를 제거해 Django `/travel/directions/`로 전달합니다. 별도로 선택한 출발지는 `TripRoute.start`에 좌표로 저장하여 상세·수정 화면에서도 복원합니다. Django는 위치 2~13개(코스 최대 12곳 + 별도 출발지), 유한한 좌표, 지원 이동 수단을 검증합니다. 명시적 요청마다 공급자를 조회하되, 성공한 구간의 typed `DirectionsRoute` 행은 마지막 동기화가 설정 간격보다 오래됐을 때만 갱신합니다. 실패 구간은 전체 합계를 `null`로 유지하고, 저장 데이터가 있으면 `stale` 경고와 함께 반환합니다. 외부 오류 전문이나 인증키는 반환하지 않습니다.

공식 API:

- [카카오맵 도보·대중교통 경로](https://developers.kakao.com/docs/ko/kakaomap/rest-api): `/v2/routing/walk`, `/v2/routing/publictraffic`
- [카카오모빌리티 자동차 길찾기](https://developers.kakaomobility.com/guide/navi-api/directions): `/v1/directions`

API별 일간 쿼터와 앱 권한이 적용됩니다. 한 코스는 인접 장소 사이의 구간 수만큼 호출하며, 이동 수단별로 별도 조회합니다.

## 검증

격리 PostgreSQL에서 typed 길찾기·legacy 호환 테스트 14개와 기존 travel 회귀 테스트 18개를 통과했고, 영향받는 frontend 테스트 9개와 Next 프로덕션 빌드를 통과했습니다. 허가된 루트 키를 메모리와 stdin으로만 전달한 실제 호출에서 자동차 944m/249초, 도보 1195m/1223초, 대중교통 1815m/1309초의 provider 경로가 DB에 저장됐습니다.
