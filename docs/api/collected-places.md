# 수집 장소 조회와 코스 지도

## 2026-10-02 지도 목록 공급원 변경

코스 작성 지도의 주변 장소 목록은 카카오 실시간 API로 변경했다. [현재 조회 규칙](travel.md#지도용-카카오-실시간-조회-2026-10-02)을 따른다. 아래 수집본 전환 당시의 지도 요청·5분 캐시 설명은 과거 동작이다.

- `/api/v1/places/live/`에서 조회만 하고 원본 결과를 Place DB에 자동 저장하지 않는다.
- 주변 핀 자동 표시 금지, 선택 장소의 점, 코스 순서 핀, 구장 시설 별도 목록, 숙박 전용 조회는 유지한다.
- 기존 소상공인·공공 수집 파일, 수집 API, RAG 및 챗봇 자동 코스 후보 파이프라인은 삭제하거나 변경하지 않았다. 이번 전환은 지도 목록에 한정한다.
- 로컬 변경이며 개발·운영 서버에 배포하지 않았다.

## 2026-09-30 로컬 변경

### 구장 소속 먹거리·시설 분리 (위치 대조는 부분 완료)

- `GET /api/v1/places/stadium-facilities/?stadium=JAMSIL`: 9개 구장 485건(먹거리 385, 편의시설 100)을 일반 주변 수집 목록과 별도로 제공한다. 원본 자리어때 CSV는 수정하지 않는다.
- 먹거리 원본의 `in_stadium_flag`에 따라 내부 348건과 외부 부속 37건을 구분한다. 편의시설의 `실외`는 입장권 없이 접근 가능한 외부라는 뜻이 아니므로 명시적 외부 표기가 없으면 내외부 미확인으로 둔다.
- 구장·층·구역·개별 레코드 ID를 유지하여 같은 브랜드의 다른 지점을 합치지 않는다. 기존 원문 확인일과 이번 핀 대조일도 구분하며 현재 영업은 미확인이다.
- `stadium_facility_pins.json`에 원문/안내도 링크와 근사 핀을 별도 관리한다. 현재 잠실 21, 광주 21, 수원 32로 총 74개다. 나머지 6개 구장, 외부 매장, 편의시설 전체의 좌표 대조는 완료되지 않았다. 미대조 행은 좌표를 임의로 채우지 않는다.
- 핀은 안내도 번호·구역과 건물 방향을 대조한 근사점이다. 30~40m 표시는 검토 여유이지 측량 정확도 보증이 아니다. 실내 이동 경로·출입구로 쓰지 않는다. 층별로 펼쳐진 안내도를 실제 지상 거리로 간주하지 않는다.
- 잠실은 사용자 첨부의 이전 안내도와 2026년 사진의 매장/번호가 달라, 2026년 사진을 기준으로 대조했다. 사진을 저장·재배포하지 않고 원문으로 연결한다.
- `/routes/new`에서 `주변 장소` / `구장 먹거리·시설`을 전환한다. 선택한 매장 핀만 표시하는 원칙은 유지한다. `/dev/stadium-food`에서는 층별 검토 핀과 안내도 링크를 확인할 수 있다.
- 공공 수집본에는 구장 매장이 종합운동장 대표 좌표에 중복으로 등록된 사례가 있다. 구장 지점명과 주소가 모두 일치하는 65건에 `stadiumAffiliation` 후보 표시를 추가했다. 내외부는 확정하지 않고 원래 좌표/ID/검색 결과를 유지한다. 단지 주소만으로 판정하지 않으며, 구·신구장이 주소를 공유하는 대전은 후보 자동 판정에서도 제외한다. 후보 판정은 전수 매칭이 아니다.
- **자동 코스 생성의 포함·제외 규칙은 변경하지 않았다.** 신규 구장 목록을 LLM 도구에 자동 주입하지 않으며, 수동으로 담는 기존 동작은 유지한다. 공공데이터 후보 정보는 검색 결과의 부가 필드일 뿐 제외 조건이 아니다.
- 관련 검증: 백엔드 `travel.test_stadium_facilities`, 프론트 `tests/stadium-facilities.test.mjs`. 구장 위치·숙박·코스 규칙 회귀 테스트와 함께 실행한다.

### 기존 지도·숙박 변경

- 주 코스 작성 화면의 숙박은 수동 카카오 AD5 조회로 전환했다. 먹거리·카페·산책 수집본 조회는 그대로 유지한다. 아래 2026-09-29 기록의 `숙박 미연결`은 수집본 자체의 상태이며, 별도 실시간 숙박 패널과 구분한다.
- `POST /api/v1/places/lodging/`: 숙박 전용 분류·검색어만 허용하고 응답은 `no-store`다. 15건/페이지, 최대 3페이지/검색어이며 ID로 중복 제거한다. 반경 내 모든 숙소를 보장하지 않는다. `여관,모텔`은 `모텔·여관(통합 분류)`로 표시하며 임의로 세부 업종을 확정하지 않는다.
- 숙박 이름·주소·분류·좌표는 화면 메모리에서만 사용한다. 저장 시 `kakao-lodging:<조회 종류>:<ID>`, 자체 표시명·숙박 대분류·방문 순서만 남기고 좌표는 `null`로 제한한다. `travel.0013_kakao_lodging_references`가 기존 참조 제약을 확장한다.
- 저장 숙소 복원은 사용자 요청 시 동일 종류의 주변 검색 결과에서 ID를 다시 찾는다. ID 단건 조회가 아니므로 검색 결과 제한·변경 때문에 복원하지 못할 수 있다. 다른 숙소로 자동 대체하지 않는다. 숙박 포함 코스는 좌표를 지속 캐시하는 길찾기 API를 호출하지 않고, 조회된 지점의 직선만 연결한다.
- `data/preprocessed/stadium_locations.json`의 9개 1군 시설 중심점을 프론트·경기장 DB·RAG 구장 앵커에 적용한다. `baseball.0007_reviewed_stadium_locations`는 기존 DB 좌표를 보정하며, 기존 CSV와 임베딩을 덮어쓰지 않는다.
- 공공 수집본은 옛 중심의 검증을 먼저 수행한 뒤 새 중심 반경 2.5km로 재필터링한다. 원본 37,027건과 반환 건수는 다르다. 새 원의 옛 수집 범위 밖 부분은 미수집이며 재수집한 것으로 표시하지 않는다.
- `/dev/stadium-locations`는 개발 모드 전용 검증 화면이다. 위성/일반 지도 전환, 시설 전체 맞춤 확대, 이전 핀 비교, 검색 반경 보기를 지원한다. 검색 원과 구장 시설 테두리는 별개다.
- 테두리는 OSM의 확인된 건물·그라운드·관중석·부속동 외곽을 모두 포함하는 사각형 또는 모서리 절삭 다각형이다. 인접 출입 공간을 위한 20m 여유를 둔다. 법적 부지·정밀 측량 경계나 공유 주차장/종합운동장 전체 영역은 아니다.
- 광주: ㄷ자 내야 건물만 사용하던 오류를 수정하고 필드·외야 관중석·외야 부속동·야구박물관을 추가했다. 공식 구장 안내도, 설계사 전경, 구단 시설관리 문서로 구성 요소를 대조했다. 무등야구장·임동119안전센터는 제외한다.
- 대전: 새 볼파크 내야 및 별도 외야 관중석 건물과 그라운드를 함께 포함한다. 옛 이글스파크는 제외한다. 수원: 필드 내부 링이 아닌 전체 관중석 건물의 외곽을 사용한다. 나머지 6개 구장도 전체 건물과 별개 인접 시설을 위성 화면으로 점검했다.
- 경계 원본은 `stadium_boundaries.json`, 프론트 사본은 `stadium-boundaries.ts`다. `fetch-stadium-boundaries.ps1`은 허용된 공개 OSM 요소만 읽고, `sync-stadium-*.mjs --check`로 사본 일치를 확인한다. © OpenStreetMap contributors / ODbL 링크를 검증 화면에 유지한다.
- 이 변경은 로컬에만 적용했으며 개발·운영 서버에 배포하지 않았다.

## 화면 동작

- 카카오 지도 SDK는 지도·좌표·오버레이를 표시한다. 장소 검색 SDK는 로드하지 않는다.
- 구장 좌표는 등록된 데이터 사용. 구장 위치 확인을 위한 외부 검색도 하지 않는다.
- 주변 장소 전체 핀은 표시하지 않는다. 목록에서 명시적으로 선택한 장소 1개,
  코스에 담은 장소, 직접 그린 경유 지점의 핀과 순서 번호는 유지한다.
- 선택만 한 장소는 정확한 좌표를 중심으로 작은 점을 표시한다. 먹거리·카페 등의 문양은
  코스에 담은 장소의 순서 핀 위에만 표시하며, 문양 때문에 좌표 기준점이 움직이지 않는다.
- `동선으로 코스 짜기` 모드는 장소 목록을 요청하지 않는다.
- 장소 목록은 구장별 API 요청 하나로 읽고, 브라우저에서 5분 재사용한다.
  진행 중 요청은 공유하며 화면 이탈/구장 전환 후 늦은 응답은 무시한다.
- 검색어·분류는 수집 목록을 필터링할 뿐 외부 검색을 실행하지 않는다.
- 기존 길찾기 제공자 호출은 유지한다. 장소 검색과 경로 계산은 별개다.

## API

`GET /api/v1/places/collected/?stadium=JAMSIL`

- 공개 읽기 전용. `stadium` 하나만 허용하며 등록된 구장 코드인지 검증한다.
- `200`: `status`, `snapshotId`, `stadium`, `radiusM`, `places`, `count`, `warning`, `lodging`.
- 장소 필드: `placeId`, `name`, `lat`, `lng`, `kind`, `category`, `subcategory`, `cuisine`,
  `address`, `phone`, `distance`, `detail`, `source`, `collectedAt`, `referenceMonth`,
  `verificationStatus`, `cafeType`. 원천 전체 `source_fields`는 브라우저에 보내지 않는다.
- `placeId=collected:<SBIZ|PARK|TOUR>:<source_id>`: 카카오 ID와 구분하며 코스 저장·챗봇 담기에서도 유지한다.
- `400`: 잘못된 구장/누락/중복/추가 파라미터.
- `503`: 수집본 누락·손상·검증 실패. 실패를 빈 목록이나 실시간 외부 검색으로 대체하지 않는다.
- 파일의 체크섬·건수·ID·반경·좌표·출처·검토 상태를 검증하고 구장별 결과를 메모리에 캐시한다.
  파일 변경 시 다시 검증한다. 파일·기존 Place 테이블·RAG 테이블에 쓰지 않는다.

## 데이터 범위와 제한

- 9구장, 직선 반경 2.5km 공공장소 후보 37,027건. 원본은 그대로 보존한다.
- 음식점·술집→먹거리, 카페/디저트→카페·디저트, 공원/산책 후보→산책,
  놀이시설→실내 놀거리, 확인된 편의점→편의점. 미검토 편의점 파일은 읽지 않는다.
- 원천 중분류·소분류로 음식 분류를 매핑한다. 매장명으로 메뉴·좌석을 추정하지 않는다.
- 수집일 2026-09-27과 소상공인 원천 기준월 202606은 구분한다.
- 영업/메뉴/예약 가능 여부는 미확인. 산책 좌표는 대표점이며 입구·보행 경로가 아니다.
- 구장 내부 매장 및 출처 간 중복 후보가 포함될 수 있다. 코스 추천 시 출입 가능 여부를 확인해야 한다.
- 숙박 파일은 Google Place ID만 보관한다. 이름·좌표가 없으며 상세 조회는 이번 작업에서 연결하지 않았다.
  `lodging.status=details_unavailable` 및 화면의 `숙박 미연결`로 구분한다. 카카오 숙박으로 대체하지 않는다.

## 챗봇

`search_places`, `search_tourism`은 같은 수집본만 읽는다. 명시적 `stadium_code`를 우선하며
코드가 없으면 요청 좌표에서 가장 가까운 수집 구장 범위를 사용한다(5km 밖이면 거부).
최대 15건/페이지, 3페이지로 제한한다. 정확한 이름·주소·업종 단어와 분류를 사용한다.
조건 미일치는 빈 검색 결과로 알리고, 데이터 장애는 별도 오류로 알린다.
공개 코스·RAG는 순서/일반 설명 참고용이지 수집본에 없는 장소를 보충하는 근거가 아니다.
이 원칙은 도구 공급원과 프롬프트에 적용했으며 LLM 최종 문장의 모든 사실을 검증하는 후처리는 별도 작업이다.
