# 장소 지식 저장 규약 1차

식당·카페 등 기존 장소에 검증한 메뉴와 후기 정보를 연결하기 위한 백엔드 저장 틀이다. 원문을 쌓는 저장소가 아니라, 항목별 관찰과 확인 상태를 기록한다. 현재 코스 작업자는 **현재 요청에서 필요한 키워드만** 추출한다. 한 매장에 여러 출처의 긍정·부정 근거가 함께 존재할 수 있다.

2026년 10월 2일 로컬 Docker DB에 저장 테이블 마이그레이션 0014·0015를 적용했다. 10월 5일 활성 코스 경로에 `llm/v1/rag/course/evidence_memory.py`를 연결했다. 현재 후보의 동일 ID 근거를 읽고, 필요하면 OpenAI 웹 검색의 실제 페이지 열기 기록을 대조한다. Serper 수집기가 아니다. 새 실제 가게 자료의 일괄 적재나 원격 서버 배포는 하지 않았다. 최신 설정과 검증 범위는 [공용 장소 근거 연결](shared-place-evidence.md)을 따른다.

현재 요청의 메뉴·음식 분류·후기 특징을 검증한다. 기본 이름·브랜드·업종으로 확인되는 내용과 추가 근거가 필요한 내용을 구분한다. 후기 특징은 `review_feature` 형식이며 출입·야간 개방·접근성의 보장이 아니다. 정확한 장소 ID로 승인 관찰을 읽고, 검토된 URL 정책에 해당하는 근거만 저장한다. 원문 전체는 저장하지 않고 조사 이력의 재검색 대기시간을 실제 코스 경로에서 확인한다.

수집 장소와 기존 분석을 검색하는 [로컬 장소 RAG](place-rag.md)는 별도로 유지한다. 새 키워드는 실시간 DB 조회로 읽어 정적 장소 인덱스 재빌드가 필요하지 않다. RAG 안의 실험 기록은 자동으로 승인된 관찰이 되지 않는다.

## URL 조회 뒤 키워드만 누적하는 연결부

`place_keyword_memory.record_keyword_memory(place_id=..., source_id=..., keywords=[...])`는 **검증 완료된 내부 결과**를 받는다. 외부 HTTP API나 LLM의 쓰기 도구가 아니며 자체적으로 본문을 읽거나 근거를 검증하지 않는다. 동일 지점 확인과 실제 근거 확인을 마친 작업자만 호출해야 한다.

- 기존 장소 ID·등록된 출처에 연결한다. API 응답의 상호·주소·좌표를 이 저장기가 복사하거나 동명 매장을 합치지 않는다.
- `menu`, `cuisine`, `review_feature`의 정규화 명칭, 적용 조건, 관찰 방향, 근거 종류, 독립 경험 키, 확인·만료 시각만 관찰에 기록한다. 자유 서술 요약은 받지 않고 짧은 상태 라벨을 코드가 만든다.
- 원문·인용문·HTML·리뷰 작성자·사진·API 응답 전체 같은 임의 필드는 거부한다. 출처 URL과 종류는 별도 출처 메타데이터로 참조한다.
- 한 번 검증한 자료에서 얻은 여러 키워드를 현재 질문과 관계없이 묶어 저장한다. 같은 출처 버전·장소·키워드·조건·경험이면 중복되지 않는다. 같은 버전을 다시 넣어 확인 시각이나 유효기한만 늘릴 수 없다.
- 새 근거는 새 출처 버전으로 추가하고, 수정된 옛 근거는 명시적으로 철회한다. 반대 관찰을 지우거나 키워드가 없다는 이유로 미판매라고 저장하지 않는다.
- 출처 저장 조건을 새로 조회한다. 키워드로 변환했다는 이유로 `unreviewed`·`blocked`를 자동 승인하지 않는다. 이번 작업에는 카카오 출처의 저장 승인 처리가 없다.

`retrieve_keyword_memory()`는 정확히 정규화된 키워드로 현재 유효한 승인 관찰을 반환한다. 만료·철회·출처 조건 변경을 즉시 반영한다. 후기의 날짜·광고·시간대·좌석 등 적용 조건도 검사한다. 긍정·부정 근거는 따로 반환하며 결과는 매장 전체의 확정 판정이 아니다. 최대 500행을 검사하고 결과 제한이나 검사 한도에 걸리면 `truncated=true`로 표시한다.

챗봇의 기존 `search_place_knowledge`에 `keyword_term`을 지정하면 `keyword_memory`에 이 관찰을 함께 반환한다. 일반 장소 조회는 기존대로 동작한다. 모델용 경로는 시간·상황 조건을 받지 않으므로 제한된 후기를 일반 특징으로 돌려주지 않는다. DB가 없거나 읽기 실패하면 `memory_unavailable`이며 유료 검색으로 전환하지 않는다.

저장·조회 함수 자체에는 외부 검색/모델/임베딩 호출이 없다. 현재 코스 작업자는 이 함수들과 같은 검증 모델을 이용해 조회·허용된 키워드 증분 저장을 수행한다. 원문이 없는 것만으로 이용 조건을 코드가 판별하는 것은 아니므로 출처 허용 상태를 별도로 유지한다.

## 1차 범위

속성은 `cuisine` 음식 분류, `menu` 판매 메뉴와 `review_feature` 후기 키워드다. 기존 `quietness` 조용함, `cleanliness` 물리적인 청결 형식도 호환을 위해 유지한다. 신규 후기 수집은 두 항목에 한정하지 않고 `review_feature`의 정규화 명칭으로 여러 특징을 저장한다. 식당뿐 아니라 카페에도 연결할 수 있다. 동의어 처리는 저장 이전 단계에서 수행하며 저장 함수가 모델을 호출하지 않는다.

장소 기본정보의 종류는 숙박·산책·시설 등도 표현할 수 있지만, 정확한 영업시간·가격·체크인·산책로 거리 등 전용 수치 속성은 이번 버전에 구현하지 않았다. 후기의 ‘가성비가 좋았다’, ‘주차하기 편했다’는 저장할 수 있지만 공식 가격이나 주차 정책으로 취급하지 않는다.

## 네 가지 저장 단위

| 모델 | 저장하는 내용 | 관계 |
| --- | --- | --- |
| `PlaceKnowledge` | 장소 ID, 이름, 지점, 주소, 좌표, 종류, 기본정보 출처·버전, 구장 소속 | 기존 수집 장소 ID를 그대로 사용 |
| `PlaceKnowledgeSource` | 출처 식별 키, URL, 종류, 수집·게시 날짜, 저장 조건 | 한 출처에 여러 관찰 연결 가능 |
| `PlaceKnowledgeObservation` | 특정 장소의 특정 속성에 대한 관찰, 긍정·부정·미확인, 검증 상태, 시간 조건 | 장소 하나와 출처 하나에 연결 |
| `PlaceEnrichmentAttempt` | 검색·읽기·추출 시도의 결과, 호출 수, 크레딧, 비용, 다음 재시도 시각 | 근거를 못 찾은 경우에도 조사 이력 보존 |

물리 테이블 이름은 각각 `travel_placeknowledge`, `travel_placeknowledgesource`, `travel_placeknowledgeobservation`, `travel_placeenrichmentattempt`다. 외부 원문, HTML, 사진, 작성자 이름·프로필, 임베딩, 원본 API 응답을 담는 필드는 없다. 짧은 summary는 자체 작성 요약을 위한 필드이며, 길이 제한이 원문·개인정보 자동 탐지를 의미하지는 않는다.

## 장소 연결과 구장 내부 구분

`place_id`에는 `collected:SBIZ:...`, `collected:PARK:...`, `stadium-facility:...` 등 기존 ID를 보존한다. 기존 `Place`는 카카오 ID 중심이고 수집 목록은 파일 기반이므로 해당 테이블로 강제 변환하지 않는다. 같은 이름이라는 이유로 지점이나 출처 간 장소를 자동 병합하지 않는다.

`base_source`, `base_version`, `base_checked_at`은 기본정보가 어디서 왔는지 나타낸다. 기본정보 등록기는 아직 연결하지 않았으므로 향후 등록 단계에서 실제 수집 목록의 ID·이름·주소를 대조해야 한다. 문자열 ID가 유효하다고 실제 존재하는 매장임을 자동 인증하지는 않는다.

| 필드 | 의미 |
| --- | --- |
| `stadium_scope=unknown` | 소속 미확인 |
| `external` | 구장과 별개인 일반 외부 장소 |
| `stadium_internal` | 구장 내부 시설 |
| `stadium_external` | 구장에 부속된 외부 시설 |
| `stadium_code` | 소속 구장 코드. 구장 시설이면 필수 |
| `floor`, `zone` | 층과 구역. 모르면 빈 값 |
| `requires_ticket` | 입장권 필요 여부. 미확인은 null |

좌표가 없으면 위도·경도를 함께 null로 두고, 범위 밖 좌표나 한쪽만 있는 좌표는 거부한다. 소속과 입장권 필요 여부는 별도 정보다. 구장에 가깝다는 이유로 내부라 판정하지 않으며, 이 표의 값을 저장한다고 자동으로 코스에서 제외하지 않는다.

## 메뉴와 음식 분류 저장 예시

아래는 실제 매장이 아닌 설명용 예다.

| 필드 | 값 |
| --- | --- |
| `attribute` | `menu` |
| `term` | 돈까스 |
| `observed_label` | 등심 돈카츠 |
| `qualifiers` | 등심 |
| `polarity` | `positive` |
| `basis` | `menu_listing` |
| `summary` | 해당 지점 메뉴 목록에서 등심 돈카츠 확인 |
| `review_status` | `accepted` |

`term`은 검색에 사용할 정규화 명칭, `observed_label`은 실제 관찰한 짧은 명칭이다. `qualifiers`는 등심·치즈 등 해당 메뉴의 세부 조건이다. 등심 돈까스가 확인됐다고 치즈 돈까스도 판매한다고 판단하지 않는다. 구조는 동의어를 저장할 수 있을 뿐 동의어 사전을 생성하거나 지점을 확인하는 모델 기능을 수행하지 않는다.

`polarity`는 positive, negative, neutral, unknown 중 하나다. 메뉴 목록에서 못 찾은 것은 unknown이며, API 실패 역시 미판매의 증거가 아니다. 미판매를 검증 완료로 저장하려면 `explicit_non_sale` 근거 유형이 필요하다. 단, 플래그만으로 실제 미판매 문장의 의미를 검사하는 것은 아니므로 등록기는 원문 대조 등 별도 검증을 수행해야 한다.

## 질문과 별개로 모으는 후기 키워드

현재 질문이 돈까스인지 조용한 식당인지에 따라 읽은 리뷰의 나머지 특징을 버리지 않는다. 추출기는 실제 읽은 본문에 있는 재사용 가능한 특징을 함께 추출하고, 검증기는 각 특징을 개별 검증한 뒤 저장기에 전달해야 한다. 모든 웹사이트의 모든 리뷰를 읽는다는 뜻이나, 본문에 없는 특징까지 생성한다는 뜻은 아니다.

| `review_category` | 담을 수 있는 키워드 예 |
| --- | --- |
| `atmosphere` | 조용함, 대화하기 편함, 아늑함, 전망 |
| `cleanliness` | 매장 청결, 식기 청결, 화장실 청결 |
| `space` | 넓은 좌석, 좌석 간격, 편한 의자 |
| `service` | 직원 친절, 빠른 음식 제공, 짧은 대기 |
| `value` | 가성비, 넉넉한 양 |
| `food` | 담백한 맛, 매운맛, 신선함에 대한 경험 |
| `facilities` | 콘센트, 와이파이, 유아 의자 이용 경험 |
| `access` | 주차 편리, 대중교통 접근, 유모차 이동 경험 |
| `suitability` | 혼밥, 데이트, 가족 방문, 단체 이용 적합성 |
| `other` | 위 분류에 없는 근거 있는 신규 특징 |

이 표는 초기 분류와 예시이지 키워드 허용 목록이 아니다. `term`에 정규화한 짧은 명칭을 저장하므로 새로운 특징이 생겨도 DB 스키마를 바꾸지 않는다. 동의어가 별도 키워드로 흩어지지 않도록 추출·등록 단계에서 표준 명칭을 맞춰야 한다. 이 저장 모듈에는 자동 동의어 통합 기능이 없다.

모든 신규 후기 관찰은 `attribute=review_feature`, `review_category`, `term`, `polarity`, 자체 작성 `summary`를 갖는다. 고객 경험은 `basis=customer_experience`, 출처 종류는 `customer_review`로 분리한다. 플랫폼 태그나 업주 홍보를 실제 후기로 검증 완료 처리하지 않는다. ‘깔끔한 맛’은 음식 평가, ‘깔끔한 인테리어’는 공간·분위기 평가이며 물리적 청결로 바꾸지 않는다. 이런 의미 검증은 추출·검증 단계의 책임이다.

예를 들어 가상의 리뷰가 ‘테이블이 깨끗하고 좌석도 넓다. 직원은 친절하지만 가격에 비해 양이 적고, 주말에는 시끄럽다’라면 다음처럼 분리한다. 아래는 실제 수집 결과가 아닌 설명용이다.

| 분류 | 정규화 키워드 | 방향 | 적용 맥락 |
| --- | --- | --- | --- |
| 청결 | 매장 청결 | 긍정 | 리뷰에서 확인한 범위 |
| 공간 | 넓은 좌석 | 긍정 | 리뷰에서 확인한 범위 |
| 서비스 | 직원 친절 | 긍정 | 리뷰에서 확인한 범위 |
| 가격 체감 | 가성비 | 부정 | 리뷰에서 확인한 범위 |
| 분위기 | 조용함 | 부정 | 주말 |

긍정적인 특징만 고르지 않고 부정·불명확한 관찰도 분리해 보존한다. 없는 언급은 키워드를 만들지 않는다. 추출이 완전했는지 여부는 저장된 행 수로 알 수 없으며, 향후 추출기는 본문 분할과 출력 잘림을 따로 관리해야 한다. 저장 함수는 전달된 목록을 질문 키워드로 필터하거나 일부만 잘라 저장하지 않는다.

## 후기의 경험과 적용 조건

기존 조용함·청결 속성은 `term`을 비운 형식을 유지한다. 코스 어댑터는 적용 조건이 없는 `review_feature`의 ‘조용함’, ‘매장 청결’, ‘매장 청결함’을 두 후기 속성으로 읽을 수 있다. 원본 행은 바꾸지 않으며 그 밖의 임의 키워드를 자동 변환하지 않는다.

`observed_on`에는 확인된 방문일 또는 해당 후기 게시일을 쓰고, `observation_date_kind`로 visited 또는 published를 구분한다. 수집 날짜를 후기 날짜로 넣지 않는다. `experience_key`는 같은 후기·재게시를 묶는 불투명 식별자이며 작성자 이름을 담지 않는다. 독립 후기 수 집계는 아직 저장 모듈에 연결하지 않았다.

```json
{
  "scope": "limited",
  "weekdays": [0, 1, 2, 3, 4],
  "start_minute": 720,
  "end_minute": 1080
}
```

이 맥락은 한국 시간 월요일부터 금요일, 12시부터 18시까지를 뜻한다. 실제 방문 구간 전체가 들어와야 재사용한다. 시간이 없는 추천에는 제한된 후기를 적용하지 않는다. 자정을 넘는 제한 구간은 1차에서 지원하지 않는다.

신규 후기의 `qualifiers`는 시간 이외의 적용 조건이다. 예를 들어 ‘테라스에서 반려견 동반이 편했다’는 `좌석:테라스`, `동반:반려견`을 함께 기록한다. 재조회 시 호출자가 확인한 `review_conditions`에 저장된 조건이 모두 있어야 반환한다. 실내에서도 가능하다거나 공식적으로 반려동물을 허용한다는 뜻으로 확장하지 않는다. 공휴일·경기일·혼잡도 판단기는 없으며, 조건을 정확히 표현·확인하지 못하면 `context.scope=unknown`으로 유지한다. 조건을 지우고 일반 특징으로 만들지 않는다.

`promotion=not_disclosed`는 광고 표시를 발견하지 못했다는 의미이지 광고가 아님을 보증하지 않는다. 기본 재사용 함수는 광고 표시가 있거나 불명확한 후기와 관찰 날짜가 180일보다 오래된 후기를 제외한다. 이 180일은 법적 보관 기한이 아니라 기존 후기 검증 기준에 맞춘 추천용 유효성 기준이다.

## 검증 상태와 재사용

| 검증 상태 | 의미 |
| --- | --- |
| `pending` | 아직 검증하지 않은 관찰 |
| `accepted` | 출처와 해당 관찰의 근거 확인을 마친 기록 |
| `rejected` | 해당 관찰을 근거로 채택하지 않음 |
| `retracted` | 이전 기록의 사용을 철회함 |

accepted는 매장 전체의 특징 확정이나 사용자 요구 충족 판정이 아니다. 후기 한 개를 accepted로 저장하더라도 곧바로 ‘조용한 식당’이라고 답하지 않는다. 긍정·부정 근거를 모두 보존하고, 현재 코스 어댑터에서 독립 경험 중복 제거와 충돌 판정을 수행한다.

검증 완료 기록은 동일 매장 확인, 실제 근거 확인, 유효기한이 필요하다. 웹 출처는 본문을 읽었어야 하며 검색 요약만으로는 accepted가 될 수 없다. 추론·근거 부족은 검증 완료로 저장하지 않는다. 이 모듈은 검증 플래그를 자동 생성하지 않으며 신뢰할 수 있는 내부 등록기에서만 호출한다.

`reusable_observations()`는 속성·정규화 명칭을 정확하게 조회한다. `attribute="review_feature", term=None`이면 재사용 조건을 통과한 모든 신규 후기 키워드를 반환하며, 특정 `term`을 주면 해당 특징만 반환한다. 만료·철회·미검증 기록과 적용되지 않는 시간·상황 조건을 제외한다. 반환값은 근거 행의 목록이다. 코스는 `EvidenceMemory`에서 같은 유효성 규칙으로 관찰을 읽고 `KnowledgeFoodVerifier`·`KnowledgeReviewVerifier`에서 메뉴 세부 조건, 독립 후기 수, 충돌/미확인과 방문 시간 적용을 판정한다. 예전 OpenAI 검색 검증기는 비교용으로 남아 있다.

## 정보 유효기한과 출처 보관 기한

두 기한은 의미가 다르다.

- 관찰의 `valid_until`: 추천 정보로 재사용할 수 있는 기한. 예를 들어 메뉴가 오래돼 다시 확인해야 할 시점이다. 속성별 기본 기간은 아직 정하지 않았으며 검증 완료 저장 시 명시해야 한다.
- 출처의 `retention_until`: 해당 출처의 보관 조건에 따른 기한이다. temporary 출처에는 반드시 지정한다.

출처 정책은 unreviewed, allowed, temporary, blocked로 기록한다. 허용 속성 목록과 검토 근거·시각도 남긴다. 특정 사이트를 자동 허용하는 기본 목록이나 법률 자동 판정은 없다. 미검토 출처는 메타데이터를 등록할 수 있지만 관찰 내용을 저장하려면 조건 확인이 필요하다. 기존 두 후기 속성의 허용을 새 `review_feature` 전체 허용으로 자동 확대하지 않는다.

현재는 기한 종료나 정책 철회 시 재사용에서 제외하는 검사를 구현했다. 만료 데이터의 실제 삭제 배치·백업 정리·기존 임베딩 삭제는 미구현이다. 따라서 보관 기한이 있는 실제 데이터를 대량 적재하기 전 삭제 절차를 추가해야 한다. 지금은 실제 적재와 임베딩 생성을 하지 않는다.

## 중복 방지와 수정 이력

`record_observation()`에 같은 `ingest_key`와 같은 내용을 다시 전달하면 기존 행을 반환한다. 같은 키로 다른 내용을 덮어쓰면 거부한다. 출처의 URL·본문 버전 식별 정보와 관찰 내용도 일반 save에서 덮어쓰지 못하게 한다. 새 확인 결과는 새 키로 추가하고, 필요하면 이전 행을 retracted로 바꾼다.

`record_review_observations(place=..., source=..., observations=[...])`는 검증된 한 후기의 여러 관찰을 묶어 저장하는 내부 함수다. 같은 장소·출처·경험 식별 키를 공유하고, 관찰별 수집 키는 구분한다. 하나가 잘못되면 묶음 전체를 되돌리며 같은 묶음을 다시 넣어도 중복 행을 만들지 않는다. 한 리뷰에서 8개 특징을 추출해도 독립 후기 8개로 세지 않는다. 원문이나 모델 출력 JSON을 무검증으로 받는 외부 API가 아니다.

검증되지 않은 pending 기록의 내용이나 확인 플래그를 고치는 경우도 새 버전을 등록한다. 기본정보는 갱신할 수 있고, 출처 저장 정책은 철회·수정할 수 있다. 호출자의 오래된 출처 객체가 아니라 DB의 현재 정책을 확인한다.

검증은 내부 서비스 함수 또는 모델 save를 통해 수행한다. `bulk_create`, `QuerySet.update`, 직접 SQL은 Python 검증을 건너뛰므로 수집기에서 사용하지 않는다. DB 자체도 ID 고유성, 좌표 쌍·범위, 시각 순서, 음수 비용, 검증 완료의 최소 플래그를 제약하지만 출처 간 의미·시간 조건 전체를 DB 제약으로 보장하지는 않는다.

## 조사 이력과 비용

완료·근거 없음·접근 제한·API 오류를 별도 상태로 저장한다. `search_calls`, `model_calls`, `search_credits`, `model_cost_usd`를 분리하며 알 수 없는 비용은 null이다. 무료 사용량을 소모한 것과 비용이 0원인 것을 혼동하지 않는다. 검색어 전체·오류 원문·키·인증 정보는 이력 필드에 넣지 않는다.

`next_retry_at`은 코스 작업자가 같은 장소·조건의 상세 재검색 전에 확인한다. 근거 부족은 60분, 오류는 15분 대기하며 미확인을 미판매 사실로 저장하지 않는다. 완료 근거는 관찰의 유효기간으로 판단한다. 이 필드 자체가 스케줄러는 아니며 작업 큐나 자동 재시도 기능도 없다.

| `backend/travel/test_place_knowledge.py` | 가상 장소로 저장·재조회·거부 조건·마이그레이션 생성/되돌리기 검증 |

아래 명령은 외부 API와 프로젝트 DB에 접근하지 않는다. SQLite 테스트는 실제 PostgreSQL 배포 검증을 대체하지 않는다.

```powershell
.\.venv\Scripts\python.exe backend/manage.py test travel.test_place_knowledge --settings=travel.knowledge_test_settings --noinput
.\.venv\Scripts\python.exe backend/manage.py makemigrations travel --check --dry-run --settings=travel.knowledge_migration_settings
```

외부 식당의 요청 조건용 추출·검증→승인 관찰 연결은 완료했다. 다음 단계는 허용 출처의 실제 소량 자료로 재사용률/정확도를 확인하고, 필요한 경우 전체 키워드 추출과 다른 업종으로 범위를 넓히는 것이다. 기존 테스트 파일의 두 매장에 분위기·편의시설 정보가 추가된 상태는 아니다. 저장 구조·코스 연결 테스트는 가상 관찰을 사용했으며 실제 리뷰 대량 재분석이나 일괄 검색은 하지 않았다.

소량의 허용된 실제 자료를 대상으로 저장 근거 재사용률을 확인하는 검증은 다음 단계다. 넓게 추출하면 최초 출력 토큰은 늘 수 있으므로 무조건 무료라고 보지 않는다. 절감 여부는 이후 재사용으로 줄어드는 검색과 반복 추출을 포함해 측정한다. 원문을 통째로 `DocumentChunk`에 넣거나 채팅 기록·사용자 개인정보를 장소 지식에 섞지 않는다.
