# 출발 핀·식당 5종·숙박 및 커피 브랜드 변경 실측

2026-10-11 로컬 Docker에서 실제 모델·장소 조회·숙박 원문 검증·채팅 저장을 사용해 실행했다. 본 시험 20회는 코스 구조 검사 기준 **19회 성공, 1회 변경 보류**였다. 보류한 컴포즈 변경은 별도 세션 재시험에서 성공했다. 초기 출발지 오류 진단과 숙박 판정 전달 수정 후 재시험까지 포함하면 총 23회다.

## 조건과 측정 범위

- 출발지: 공개 장소인 잠실새내역 2호선 좌표. 모든 요청에 프런트엔드와 같은 `context.origin` 및 편집용 현재 코스를 전달했다.
- 기준 경기: 로컬 DB에 구장 연결이 있는 **2026-10-07 18:30 잠실 LG 대 두산**. 시험 시점에는 과거 경기이며 미래 경기 검증이 아니다.
- 각 음식 종류마다 새 게스트 세션에서 생성 → 숙박 변경 → 메가 변경 → 컴포즈 변경을 차례로 수행했다. 음식 종류는 양식·일식·중식·자장면·돈카츠다.
- 생성 순서: 출발지 → 구장 밖 식당 → 카페 → 구장 내부 통밥 → 경기 관람 → 아시아공원 산책. 방문지는 다섯 곳이며 출발지는 별도다. 이동수단은 도보다.
- 숙박 변경은 산책만 **주차 가능한 호텔**로 바꿨다. 호텔·주차는 검증 범위를 명확히 하기 위해 넣은 추가 조건이다. 이후 카페만 메가MGC커피, 컴포즈커피로 변경했다.
- 실제 Django WSGI 앱을 백엔드 컨테이너의 테스트용 HTTP 포트에서 실행했다. 모의 공급자 없이 운영과 같은 코드·로컬 DB·캐시·외부 서비스를 사용했다. 시간은 메시지 POST 시작부터 SSE 응답 종료까지이며, 채팅 조회로 코스와 답변 저장도 확인했다. Nginx·인터넷 사용자망·브라우저 렌더링 시간은 제외한다.
- Chrome 화면에서 잠실 구장 선택과 출발 핀 입력은 별도로 확인했다. 20건 전체를 화면 클릭으로 생성한 UI 종단간 시험은 아니다. 코스의 채팅 저장을 확인했으며 게시·공유·개인 저장 코스 등록까지 시험한 것은 아니다.
- 캐시를 매회 지우지 않았다. 원문 사전 갱신 워커도 켜져 있어 후속 요청이 앞 요청의 캐시 영향을 받는다. 동일 조건 반복 평균이나 운영 부하 시험으로 해석하지 않는다.

## 비용 산식과 계측 한계

2026-10-11 확인한 표준 단가를 사용했다. [GPT-6-luna 모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)는 100만 토큰당 일반 입력 $0.10, 캐시 읽기 $0.01, 캐시 쓰기 $0.125, 출력 $0.50이다. reasoning 토큰은 보고된 출력에 포함되므로 다시 더하지 않았다. [text-embedding-3-small](https://developers.openai.com/api/docs/models/text-embedding-3-small)은 입력 100만 토큰당 $0.02다.

[JEV 1.13의 OpenRouter 단가](https://openrouter.ai/typesafe/jev-1.13/)는 입력 100만 토큰당 $0.042, 출력 무료다. 응답의 `usage.cost`를 수집한 실행은 그 값을 우선 사용하고 나머지는 토큰으로 계산했다. 이 JEV 호출은 요청 분류기이며 숙박 브라우저 조작 모델이 아니다.

계산식은 `(일반 입력 × 0.10 + 캐시 읽기 × 0.01 + 캐시 쓰기 × 0.125 + 출력 × 0.50) / 1,000,000`에 임베딩·분류기·검색료를 더한다. [OpenAI 검색 단가](https://developers.openai.com/api/docs/pricing)는 검색 작업 1회 $0.01이며 모델 토큰 요금은 별도다.

- 숙박 변경에서 OpenAI 검색은 **0회**였다. 자장면 생성에서 메뉴 페이지 탐색을 위한 검색은 **1회**였고 $0.01을 더했다. 코스 전체가 무조건 검색료 0이라는 뜻은 아니다.
- 자장면의 직접 Responses API 호출 한 건은 최초 계측에서 캐시 세부 토큰을 놓쳤다. 앱의 정산 기록과 대조해 **입력 13,350·출력 362·모델 1회**를 복원했고, DB 조사 기록에서 검색 1회를 확인했다. 누락 입력을 전부 캐시 읽기로 계산한 하한과 전부 캐시 쓰기로 계산한 상한을 제시했다. 이 비용을 0으로 처리하거나 임의로 정확한 값이라고 하지 않는다.
- 나머지 본 시험·재시험은 콜백 모델 토큰과 분류기 토큰을 합쳐 앱 정산의 입력·출력·호출 수와 일치함을 확인했다. 초기 진단의 분류기 토큰은 전체 정산에서 세 모델 호출을 뺀 입력 2,130·출력 342로 복원했다.
- 서비스 티어가 보고된 모델 호출은 `default`였다. 추가 요금제 할인·세금·환율을 가정하지 않았다.
- **서버/Chrome CPU·메모리·네트워크, Kakao·경로 공급자 계약 요금, Codex 이용료는 이 모델·검색 합계에 포함하지 않는다.** 이번에 금액을 확정하지 못한 항목이며 비용 0으로 판정한 것이 아니다. 숙박 원문 사전 갱신은 검색·조작 모델을 호출하지 않지만 서버 운영 자원은 사용한다.

## 왜 70초가 걸리는가

양식 74.828초의 내부 계측은 요청 해석 10.767초, 임베딩 3.417초, 후보 조회·검증 22.692초, 출발지 기준 순차 선정 19.286초, 추가 카카오 단계 0.010초였다. 그 외 후보 조건 필터·시간표·최초 에이전트 처리·저장 등 세부 계측 밖 시간은 합계 약 18.656초다. 이 나머지 전체를 단일 모델 또는 단일 저장 단계 탓으로 돌리지 않는다. 병렬 준비 0.432초는 해석과 겹치므로 다시 더하지 않는다.

이 실행은 답변·해석·후보 검증 모델 11회와 분류기 1회를 사용했다. 최초 후보 조사 뒤 출발지 동선에 맞춰 후보를 다시 고르는 구간도 존재한다. 자장면에는 업종만으로 판정할 수 없는 메뉴 검증과 검색이 추가됐다. Chrome 숙소 원문을 빠르게 읽는 개선만으로 식당·카페·산책의 작업까지 없어지지 않는다.

숙박으로 **수정**하는 작업은 새 코스 전용 통합 해석·직접 응답 경로가 아니다. 기존 편집 해석, 숙박 조건 해석, 원문 검증, 시간표 재계산, 최종 답변 모델이 유지되어 본 시험 평균 61.374초였다. 원문 캐시가 있어도 이 단계들은 남는다.

다음 성능 개선 후보는 요청 안에서 확인한 후보·조건 판정의 중복 사용을 줄이고, 서로 독립적인 식당·카페 근거 조회를 제한된 병렬 처리로 묶는 것이다. 조건·방문 시점·거리·취소·조사 예산을 보존해야 한다. 이번 시험은 이 최적화를 새로 적용하거나 같은 복합 코스가 30초가 됐음을 입증하지 않았다.

## 이번에 수정한 부분과 재현

1. `arrival.py`: ‘지도에 찍은 출발지에서 출발해서 …’를 핀 참조로 해석한다. 뒤따르는 식당을 출발지 검색어로 삼지 않는다. 명시적인 새 지명은 여전히 핀을 덮어쓸 수 있고, 핀이 없으면 좌표를 요청한다.
2. `lodging.assessments()`를 생성·편집에서 함께 사용한다. 숙박 교체 결과의 검증 상태를 최종 답변에 전달하되 공개 카드에는 내부 판정·원문을 넣지 않는다. 모델과 원문 검증 기준은 유지했다.
3. 설치된 프런트엔드 패키지가 lockfile과 달라 발생한 `react-markdown` 빌드 오류는 컨테이너에서 `npm ci` 후 로컬 Compose 설정으로 재기동해 해결했다. 패키지 정의를 변경한 것은 아니다.

출발지 관련 회귀 28개, 편집·숙박 조건·후기·최종 답변 전달 관련 회귀 79개, **총 107개 통과**. `git diff --check`도 통과했다. 원문 검증 생략이나 모델 하향은 없다. 기존 미커밋 작업을 보존했고 커밋·Push·배포는 수행하지 않았다.

원본은 Git 제외 경로 `backend/artifacts/lodging-comparison-20261011/`에 보관했다. `course_matrix.py`, `matrix_verify.py`, `matrix_costs.py`, `matrix_lodging_verdict.py`와 `matrix-v1-*.json`, `matrix-v2-*.json`, `matrix-compose-probe-*.json`, `matrix-lodging-fix-*.json`, `matrix-pilot-recovered.json`, `matrix-verification.json`, `matrix-summary.json`이 재현·감사 자료다. 원본 계측에는 테스트 대화가 있으므로 공유용 문서에는 세션·쿠키·인증 정보·원문 본문을 포함하지 않았다.
