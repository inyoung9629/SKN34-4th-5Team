# 잠실 숙박 복합 수정 실패 수정 검증

검증일: 2026-10-12. 로컬 Docker의 실제 Chrome 수집 서비스와 코스 에이전트 사용.

## 재현 조건과 결과

- 요청: `난 카페 무조건 메가커피 가야해. 메가커피로 바꿔줘 그리고 산책 말고 숙박으로 일정 수정해줘`
- 실패 당시 저장된 출발지, 코스, 메모리를 그대로 재사용했다. 해당 저장 코스의 경기는 2026-10-12 잠실 18:30이며, 10월 16일 가상 경기 측정이 아니다.
- 기존 화면 요청: 약 87.5초 후 숙박 검증 실패로 복합 수정 전체 취소. 기존 코드의 에이전트 재현: 약 85.9초.
- 숙박 수집 수정 후 에이전트 재현: **41.46초, `course:edit` 성공**. 이후 중복 해석 제거 결과는 아래에 기록했다. 프런트엔드 전체 응답 시간이 아니다.
- 숙박 페이지 캐시 읽기를 비활성화해 새 Chrome 프로필로 실제 NOL 검색·상세 페이지를 읽었다. 식당·카페 등 다른 종류의 캐시까지 모두 비운 측정은 아니다.
- 결과: 메가MGC커피 삼성중앙점 → 통밥 → 잠실야구장 → 안주마을 달보드레키친 → 호텔상주. 카페·산책만 교체하고 나머지 장소와 경기 일정을 유지했다.
- 숙박 출처: https://nol.yanolja.com/stay/domestic/3012557
- 실제 페이지 상호: 잠실 상주 호텔. 주소: 서울특별시 송파구 올림픽로8길 19. 카카오 후보의 도로명·건물 번호와 일치했다.
- 재현은 저장된 입력을 별도 호출한 것으로 사용자의 대화·지도 상태에 결과를 덮어쓰지 않았다.

| 후보 | 최종 수집 시간 | 결과 |
| --- | ---: | --- |
| 호텔봄 | 2.91초 | 해당 지역 NOL 검색 결과 없음 |
| 폼호텔 | 3.76초 | 해당 지역 NOL 검색 결과 없음 |
| 칸호텔 | 2.56초 | 해당 지역 NOL 검색 결과 없음 |
| 호텔상주 | 5.67초 | 상세 페이지 및 주소 확인 성공 |

위 결과 없음은 해당 이름·지역의 NOL 검색 결과이며 실제 숙소의 부재나 폐업을 뜻하지 않는다. 숙박 수집 합계는 14.90초이고 나머지 시간에는 수정 해석, 카페 후보 선택, 일정 재계산 등이 포함된다.

## 원인과 변경

1. `document.readyState === complete`를 기다려 첫 화면에서 시간 초과. 광고 등 전체 하위 리소스 완료 대신 검색 결과·숙소 상세 본문의 준비 상태를 확인한다.
2. 준비 중인 첫 화면 검색창에 입력하거나 주소 변경만으로 검색 성공을 판단하던 경로를 제거했다. 실제 NOL UI에서 검증한 공개 검색 URL로 이동하며 후보 주소의 시·구를 함께 검색한다. OpenAI 웹 검색이나 검색 에이전트를 사용하지 않는다.
3. NOL의 `일치하는 상품이 없어요` 문구를 놓쳐 없는 후보마다 약 15초 대기했다. 안정된 빈 검색 결과를 정상 종료 조건으로 처리한다.
4. `호텔상주` / `잠실 상주 호텔`의 업종 단어 순서 차이를 허용한다. 도로명·건물 번호, 지역, 지점 번호 검사는 유지한다.
5. 실제 상세 이동에서 확인된 내부 5초 제한을 이동 명령에 한해 최대 15초로 조정한다. 요청 전체 제한시간은 넘지 않는다. 실패 단계만 제한된 필드로 남긴다.

- 이번 결과는 동일 시나리오의 성공을 확인한 것이며 모든 숙소·외부 사이트 상태나 30초 이내 응답을 보장하는 측정은 아니다.

## 후속 개선: 명확한 부분 수정의 중복 해석 제거

동일 입력·출발지·기존 코스에 대해 숙박 페이지 캐시 읽기를 끄고 두 번 측정했다. 다른 종류의 캐시는 비우지 않았으며, 두 요청 모두 실제 NOL 검색·상세 페이지를 새 Chrome 프로필에서 읽었다.

| 구간 | 1차 | 2차 |
| --- | ---: | ---: |
| 전체 코스 에이전트 | **18.87초** | **16.54초** |
| 수정 해석 | 0.029초 | 0.029초 |
| 메가커피 선택 | 0.084초 | 0.095초 |
| 숙박 선택 및 NOL 확인 | 16.964초 | 14.461초 |
| 최종 일정 재계산 | 0.861초 | 0.799초 |

- 평균 17.705초로 앞선 41.46초 측정 대비 약 57% 단축됐다. 표의 선택 시간에는 중첩된 확인 작업이 포함되므로 별도 수집 시간을 다시 더하지 않는다.
- `literal_edits.py`가 **문장 전체를 해석할 수 있고 변경 대상이 한 곳으로 특정되는** 브랜드·업종·활동 교체를 처리한다. 알려진 브랜드 및 업종 사전을 공유하며 특정 숙소나 이 시연 문장만을 하드코딩하지 않는다.
- 원문에 주차·청결·제외·특정 지점·날짜·추가 질문 등 지원하지 않는 표현이 하나라도 남으면 기존 LLM 경로로 돌아간다. 여러 카페가 있거나 같은 방문지를 연속 수정하거나 기존 브랜드 조건과 충돌해도 기존 해석을 사용한다.
- 코드로 해석한 브랜드는 실제 카카오 상호와 카페 분류로 확인한다. 단순 숙박 교체는 별도 조건 추출 LLM만 생략하며, NOL 상세 이름·주소 확인은 계속 수행한다. 명시/저장된 숙박 조건이 있으면 조건 검증을 생략하지 않는다.
- 두 실행 모두 코스 에이전트 내부의 `agent.llm()` 호출이 0회였다. 이는 외부 챗봇 분류 단계까지 모델 호출이 없다는 뜻은 아니다.
- 두 실행 모두 메가MGC커피 삼성중앙점과 호텔상주로 교체됐다. 2차 실행에서 나머지 3개 방문지의 이름·ID·좌표, 경기 데이터, 전체 방문지 수 보존을 코드로 검사했다.
- 최종 관련 회귀 테스트: `test_course_literal_edits`, `test_course_editing`, `test_course_catalog_conditions`, `test_course_recommendation_policy`, `test_lodging_chrome`, `test_lodging_conditions` **90개 통과**. 브랜드 불일치, 추가 조건의 LLM 전달, 모호한 대상, 고정/완료 방문지, 복합 수정 실패 시 전체 취소를 포함한다.
- 측정 결과를 사용자의 기존 대화나 지도에 덮어쓰지 않았다. 복잡한 조건 요청이나 다른 외부 사이트 상태까지 동일한 시간을 보장하지 않는다.
