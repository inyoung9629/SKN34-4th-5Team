# 코스 추천 속도와 필수 조건 유지 — 2026-10-12

## 적용 기준

사용자는 일반 코스를 빠르게 완성하되 엉뚱한 업종·메뉴를 추천하거나 요청한 카테고리를 반복해서 누락하지 않도록 요청했다. 이에 일반 추천에서는 평점·실내 사진의 신규 정밀 조사를 응답 대기에서 분리했다. 메뉴·브랜드, 출발지, 날짜와 경기 시각, 방문 순서, 반경, 확인된 휴무·브레이크타임, 부분 수정의 보존 범위는 유지한다.

- `COURSE_RECOMMENDATION_MODE=balanced`가 기본이다. 전체 품질 조사 경로로 되돌리려면 `strict`를 사용한다. 실행 중인 서비스의 환경 설정을 바꾸면 해당 서비스를 다시 시작해야 한다.
- 일반 추천에서 평점·실내 근거가 없다는 이유만으로 방문 자체를 버리지 않는다. 기존에 차단한 업소·유흥 업종과 확인된 품질 부적합은 계속 제외한다. 미확인을 품질 승인으로 저장하지 않으며 답변에 미확인 안내를 붙인다.
- 평점·후기·깔끔함·조용함·주차·실제 메뉴 근거 등 명시적인 조사 조건은 기존 검증 경로를 사용한다. 이 요청은 일반 추천과 같은 속도를 보장하지 않는다.
- 돈카츠 전문 업종이나 메뉴가 직접 나타나는 상호는 **추천 단서**로 쓸 수 있다. 일반 일식·중식 업종만으로 돈카츠·자장면을 확정하지 않는다. 상호 단서를 메뉴판 검증으로 표시하지 않는다. 복합·제외·알 수 없는 브랜드 조건은 사용자 원문을 검사하는 기존 선택 경로를 유지한다.
- 구장 내부 먹거리는 명시적인 내부 요청에서만 자리어때 수집 목록을 사용한다. 카카오 내부 매장으로 대체하지 않는다. 경기 후를 명시하지 않은 내부 간식은 경기 전으로 연결하며, 기존 30분 전 내부 먹거리 도착·일반 20분 전 구장 도착 규칙을 유지한다.

## 줄인 작업과 보존한 검사

새 요청을 해석하는 동안 경기 일정과 독립적인 지도 후보를 준비한다. 준비한 결과는 질문·구장·조회일과 정확한 검색 좌표·반경·업종·검색어가 같은 경우에만 재사용한다. 불완전한 공급자 응답은 성공 캐시로 삼지 않는다. 내부 요청이 있으면 식당·카페의 투기적 카카오 사전 검색은 생략한다.

혼합 코스는 각 방문의 실제 앞 지점에서 조건을 검사해, 전체 후보를 먼저 조사하고 다시 조사하는 중복을 줄인다. 같은 지점의 중복 후보도 한 번만 조사한다. 단순 코스 수정은 도구 선택과 마지막 문장 재작성 모델을 생략할 수 있지만, 별도 질문·설명·출력 형식 요구와 도구가 처리하지 못한 수정은 기존 답변 경로를 유지한다.

단순 수정의 추가 선택 모델 생략은 원문 전체가 알려진 교체 문법과 일치하고 새 메뉴·브랜드가 해석 결과에 남은 경우로 제한한다. `돈카츠 가게로 수정해줘`를 `식당`으로 잘못 요약하거나, `스타벅스로 바꿔줘`를 일반 `카페`로 요약하면 빠른 선택을 적용하지 않는다.

실측 결과를 검토하다 기존 코드가 **술집 검색 결과에 섞인 일반 음식점의 업종에 `> 술집`을 덧붙이던 문제**를 발견했다. 평점 조사에서 승인된 원래 업종을 다시 붙이던 경로에서는 가려질 수 있던 문제다. 초기 후보와 방문별 검색 두 경로에서 이 보정을 제거하고 실제 공급자 업종이 술집인 후보만 남긴다. 검증도 공개 응답의 `FOOD` 분류뿐 아니라 원래 공급자 업종까지 확인하도록 강화했다.

부분 수정에서는 공개 지도 데이터가 세부 업종을 생략해 기존 술집을 일반 식당으로 재계산하는 문제도 보완했다. 최초 생성 시 실제 공급자의 세부 업종을 서버 기억에 저장하고, 현재 지도와 서버 기억의 구장·지점·좌표·카테고리가 일치할 때만 빠진 세부 업종을 복원한다. 공개 API 필드는 늘리지 않는다. 삭제한 방문지나 바꾼 좌표·카테고리·다른 지점·이전 출발지를 복원하지 않는다. 이 보완 뒤에는 다른 장소 수정 시 술집의 기존 체류시간이 유지되는지도 별도 확인한다.

## 백그라운드 갱신

별도 `course-place-warmer` 서비스가 광주·잠실의 식당·카페·술집 자료를 준비한다. 기본 주기는 15분, 한 회 최대 6곳·120초이며 구장 중심과 네 방향, 업종을 순환한다. 요청 중에는 새 조사를 보류하고 이미 진행 중인 호출은 취소 확인 지점에서 중단한다. 실행 중인 외부 호출을 즉시 끊는다는 의미는 아니다.

큐는 최대 512개, 7일 보존이며 지점 식별 정보와 지원 메뉴명만 저장한다. 사용자 질문·출발 좌표·후기 원문·사진은 큐에 저장하지 않는다. 갱신 실패로 기존 유효 판정을 지우거나 유효기간을 연장하지 않는다. 승인·부적합 판정은 3일 이후 재확인하며 새 부적합 판정은 과거 승인보다 우선한다.

가까운 검증 후보의 우선 범위는 앞 지점에서 최대 800m, 최단 후보보다 추가 250m 이내이며 현재 검색 반경도 넘지 않는다. 먼 캐시 매장을 가까운 미검증 매장보다 우선하지 않는다.

메뉴 관찰의 영구 저장은 기존 `PLACE_EVIDENCE_STORAGE_POLICIES`가 허용한 경우에만 한다. 이 로컬 환경은 해당 목록이 비어 있어 **메뉴 자료 영구 저장이 활성화된 것은 아니다.** 큐 등록이나 조사 시도를 메뉴 검증 성공으로 세지 않는다. 초기 수동 갱신은 54.376초에 24개를 처리했고 그중 유효 품질 판정은 2개였다. 모든 매장의 근거가 미리 확보됐다는 뜻이 아니다.

## 실측 방법과 해석 범위

실제 v2 공개 채팅 API를 Django `APIClient`로 호출해 SSE 완료까지 잰다. 실제 모델·지도 공급자·저장 경로를 사용하고 관찰용 계측만 추가했다. 브라우저 렌더링·역방향 프록시·실제 HTTP 전송 시간은 제외한다. 운영 캐시를 지우지 않았으며 서로 다른 실행 사이 캐시 상태·외부 응답·모델 해석이 달라진다. 고정 상태 A/B나 코드 변경만의 인과적 단축률로 해석하지 않는다.

10월 16일 광주 14시·잠실 17시 가상 경기에서 다음 5종의 생성과 후속 수정을 양쪽 구장에 적용한다. 기본역 출발과 다른 반경 내 좌표를 섞는다.

1. 자장면 → 내부 간식 → 경기 → 술집 → 산책 / 경기 전 식당을 돈카츠로 변경
2. 카페 → 내부 간식 → 경기 → 술집 → 산책 / 카페를 메가커피로 변경
3. 식당 → 카페 → 경기 → 산책 / 카페만 삭제
4. 카페 → 경기 → 산책 / 카페 체류시간만 20분으로 변경
5. 돈카츠 → 경기 → 술집 / 경기 후 술집만 카페로 변경

완료·저장·지도용 구조·반경·중복·날짜·출발지·요청 순서·내부 출처·메뉴 일치·브랜드·부분 수정 보존을 검사한다. 술집은 실제 공급자 업종도 대조한다. 돈카츠 전문 업종 같은 추천 단서와 실제 메뉴 원문 검증은 구분한다. 신규 생성/수정 한 쌍마다 독립된 시험용 비회원으로 실행하며 운영 토큰 한도는 변경하지 않는다.

원시 계측은 Git 제외 경로 `backend/artifacts/course-latency-20261012/`에 있다. 개인 대화나 사용자 인증 정보를 공개 보고서에 옮기지 않는다. 이번 검증은 숙박·복잡한 추가 조건·동시 사용자 부하 전반을 다루는 성공률 보장이 아니다.

## 세부 업종 최초 저장·복원 후 추가 4건

복원만 추가한 첫 실행 `benchmark-balanced-metadata-4.json`은 생성 2건 통과·후속 수정 2건의 체류시간 보존 실패였다. 최초 생성 결과에서 이미 세부 업종을 버리고 있어 복원할 자료가 없었다. 최초 생성 시 서버 기억에도 세부 업종을 남기도록 수정한 뒤 `benchmark-balanced-metadata-fixed-4.json`으로 재검증했다.
