## 기록 범위

야놀자(NOL) 숙박 정보를 일반 Chrome으로 읽어 기존 코스 생성기에 전달할 수 있는지 확인했다. 서비스의 기본 숙박 조회 방식은 이 실험에서 변경하지 않았다. Chrome은 Codex가 조작한 실험용 연결이며, 서버에서 무인 실행되는 Chrome 연동을 구현한 상태가 아니다. 코스 생성 및 본문 추출에 쓰는 OpenAI/JEV 모델은 유지했다.

앞선 직접 HTTP 조회와 Docker JEV 브라우저 실험에서는 NOL 상세 정보를 확보하지 못했지만, 일반 Chrome에서는 공개 상세 페이지를 읽을 수 있었다. 이는 Docker가 차단 원인이라는 증명이나 모든 Chrome 접근의 성공 보장은 아니다.

## 적용한 실험 변경과 검증

1. 실제 v2 채팅 API를 테스트 클라이언트로 호출하고 별도 DB·Qdrant 컬렉션에서 실행했다. 사용자 대화 DB는 변경하지 않았다.
2. Chrome 실험에서 숙박 URL 발견과 본문 공급만 대체했다. `lodging._read_details`, 원문 근거 확인, `same_property`, `_normalize` 및 코스 생성 규칙은 유지했다. OpenAI native web 도구 호출은 실험 가드로 금지했다.
3. Chrome이 관찰한 원문 발췌를 LLM 구조화 추출에 전달했다. 이름·주소·출처를 임의로 확정하거나 실패한 숙소를 코스에 강제로 추가하지 않았다. 운영 코드의 Chrome 공급자로 등록하지 않았다.
4. 동적 장소 증거 RAG 읽기·저장을 우회하고 지속 캐시는 `DummyCache`, 품질 판단 캐시는 매 요청 비어 있는 메모리로 설정했다. 모델 프롬프트 캐시는 명시 모드·breakpoint 0개로 설정했고 기록된 캐시 읽기/쓰기 토큰이 모두 0임을 확인했다.
5. 고정 수집 자료·경기 일정·기존 문서 벡터 15개는 입력 자료로 유지했다. 브라우저·검색엔진·CDN 내부 캐시는 통제하지 못했다. 반복 요청에서도 페이지를 새로 열었으나 완전한 네트워크 무캐시 실험을 뜻하지 않는다.
6. 10회 모두 앱 `UsageCharge` 원장과 모델 호출 수·입출력 토큰을 대조했다. 단가를 알 수 없는 호출은 없었다. 저장용 캐시 임베딩 호출은 수행하지 않았다.
7. 첫 검사에서 표시용 `origin.name`이 추가된 객체를 전체 비교하여 출발지 보존이 잘못 실패 처리됐다. 저장된 원본의 위도·경도 비교로 집계만 교정했고 유료 실행은 다시 하지 않았다.
8. 실험 DB·컬렉션을 삭제하고 Qdrant를 시작 전 중지 상태로 복원했다. 로컬 실험 원본은 남겼다.

Chrome 전체 시간에는 작업 중개·파일 전달·대기 시간이 포함된다. 초반에 두 방식 프로세스가 일부 병행되기도 했다. 이 기록으로 서비스 응답 속도의 우열을 주장할 수 없다. 숙박 요금·빈방·10월 16일 객실 예약 가능 여부와 청결/조용함 조건도 검증 대상이 아니다.
