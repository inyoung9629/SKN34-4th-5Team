## 변경

- 단순 새 코스의 방문 종류·순서·조건 추출은 같은 모델 `gpt-6-luna`의 `reasoning_effort=low`를 사용한다. 프롬프트, 출력 스키마, 날짜 계산, 내부 출처 정책, 메뉴·브랜드·영업시간 검증을 삭제하지 않았다. 평점·청결·주차 등 명시적인 근거 요청과 금연·반려동물·인원·대안 조건은 기존 `medium`을 유지한다.
- 설정을 공유 모델에 덮어쓰지 않고 복제본에 적용한다. 다른 요청이나 부분 수정의 검증 모델 설정에는 영향이 없다.
- 카카오 등 실시간 후보 조회와 Qdrant 후보 조회를 겹친다. Qdrant 업종별 조회는 최대 2개씩 병렬 실행하고 기존 입력 순서로 병합한다. 검색어 벡터·구장·업종·검색 개수·반경·중복 제거·품질 검사 순서는 유지한다. 품질 및 증거 조사 상태 변경은 요청 스레드에서 수행한다.
- 실패·취소를 빈 후보로 숨기지 않고 기존대로 전달한다. 현재 시작된 작업을 정리한 뒤 반환한다.
- `requested_candidates_ms`, `live_ms`, `vector_ms`, `vector_wait_ms`를 추가해 다음 지연에서 방문별 후보, 실시간 조회, 저장 검색을 구분할 수 있게 했다. 병렬 구간은 합산하면 중복 시간이므로 전체 `retrieval_ms`와 구분한다.

추론 설정의 근거: [OpenAI 공식 reasoning 안내](https://developers.openai.com/api/docs/guides/reasoning). 낮은 추론 수준은 속도·토큰 사용량과 품질 사이의 조정이며, 성공률을 보장하는 설정은 아니다. 따라서 상세 조건을 유지하는 범위를 분리하고 실제 요청으로 검증했다.
