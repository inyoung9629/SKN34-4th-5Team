# 팀 develop 통합과 JEV 숙박 조사 인계 — 2026-10-08

## 반영 범위

팀 `develop`의 `33e475c`(PR #70)를 기준으로 개인 `main`의 `72f2e0f`에 있던 코스 기능과 수집 자료를 통합했다. 팀의 첨부 URL 원문 읽기, 출처 표시, 채팅 UI 및 JEV 배포 구조를 유지했다. 프론트엔드 도구 목록 테스트 두 파일의 충돌은 팀의 동적 목록 검증을 기준으로 해결했다.

- 개인 코스 생성·수정, 선택한 지도 핀, 기본 출발지, 구장 입장 시각, 자리어때 먹거리·메뉴 데이터는 유지했다.
- 숙박 조회를 Chrome 또는 JEV로 전환한 서비스 코드는 추가하지 않았다. 현재 숙박 후보 조사는 기존 OpenAI 웹 검색 경로를 사용한다.
- 첨부 입력 오류 테스트는 자체 연속 요청이 비회원 한도를 넘겨 400/404 대신 429를 받았다. 해당 테스트 클래스에서만 캐시 초기화와 높은 검사 한도를 적용했다. 실제 서비스의 요청 제한은 유지한다.
- JEV 이미지의 Windows CRLF 호환 문제를 수정했다. 빌드 시 provider 패치 대상 문자열과 Linux 실행 스크립트의 줄바꿈을 LF로 정규화한다. 브라우저 실행 권한·프록시·샌드박스 설정은 유지한다.

## 최신 JEV 실제 확인 결과

별도 Docker 이미지와 시험용 컨테이너에서 최신 팀 reader와 agent를 실행했다. OpenAI native 웹 검색과 Serper는 이 시험에 사용하지 않았다. 일반 Chrome 중개 실험과 다른 실행이다.

| 시험 | 관찰 결과 | 판정 |
| --- | --- | --- |
| JEV 이미지 빌드·기동 | Windows 줄바꿈 보정 후 성공 | 실행 가능 |
| 일반 공개 페이지 읽기 | example.com 본문과 제목 확인 | 정상 |
| NOL 글래드 강남 코엑스센터 상세 | “일시적으로 서비스를 이용하실 수 없습니다” 및 잠시 후 재시도 안내 화면 | 숙소 정보 미확보 |
| 잠실 글래드 후보 URL 조사 | Google 검색이 reCAPTCHA 화면으로 이동, agent가 blocked 반환 | 후보 URL 미확보 |
| 광주 테마모텔 후보 URL 조사 | Google 검색이 reCAPTCHA 화면으로 이동, agent가 blocked 반환 | 후보 URL 미확보 |

[민감정보를 제외한 시험 집계](jev-team70-20261008.json)에서 호출별 결과와 소요 시간을 볼 수 있다.

대상 상세 URL: https://nol.yanolja.com/stay/domestic/3012015

**reader의 알려진 문제:** 한국어 서비스 이용 불가 화면을 `ok`와 본문으로 반환했다. 이는 DOM 텍스트를 얻었다는 의미이며 숙소 정보 확인 성공이 아니다. 오류 화면을 명시적으로 거르는 후속 수정이 필요하다. 사용자 요청에 따라 확인 단계에서 멈췄고 이 판정 규칙은 수정하지 않았다.

이번 환경에서는 JEV로 숙소 정보를 확보하지 못했다. 숙박을 넣은 전체 코스를 새로 생성하지 않았고, 정확한 차단 정책·차단 원인이나 모든 환경의 실패를 확정하지 않았다. CAPTCHA를 해결하거나 우회하지 않았다. 시험 컨테이너와 전용 네트워크는 종료·삭제했다.

## 집에서 이어서 확인할 내용

개인 저장소의 `main`에 반영한 결과를 받을 수 있다. 집의 미커밋 작업을 먼저 확인한 뒤 갱신한다.

```bash
git status
git fetch origin
git switch main
git pull --ff-only origin main
```

새 코드 작업은 최신 `upstream/develop`을 확인하고 `feat/...`에서 이어간다. 저장소 루트의 `AGENTS.md`와 `docs/TEAM_GITHUB_RULES.md`를 따른다.

기존 backend 이미지를 그대로 쓰면 MCP 어댑터나 Qdrant 클라이언트가 빠져 있을 수 있으므로 `backend/requirements.txt`가 반영되도록 이미지를 재빌드한다.

실제 `.env`·API 키·DB 내용·기존 대화·사용자가 찍은 정확한 핀·Docker 이미지는 Git으로 전달되지 않는다. 집의 환경변수를 별도로 준비한다. JEV를 실행할 때 backend와 reader에 같은 비어 있지 않은 `JEV_MCP_TOKEN`이 필요하다. 설정·실행 구조는 [JEV DOM reader 문서](../JEV_CUSTOM_READER.md)를 참고한다.

[Chrome 비교 기록](chrome-lodging-20261008.md)과 해당 집계 JSON은 Git에 포함했다. 실험 전체 로그·원문은 이 컴퓨터의 Git 제외 경로 `backend/artifacts/chrome-cost-20261008/`, `backend/artifacts/jev-lodging-20261008/`에만 있다. 이 문서에는 인증 정보, IP 주소, CAPTCHA 식별자와 원본 세션 ID를 기록하지 않았다.

후속 작업은 ① 한국어 오류 화면의 성공 오판 방지 ② 집 환경에서 공개 상세 페이지 접근 확인 ③ 접근 성공 후 JEV 후보 조사와 기존 이름·주소·평점 검증 연결 순서가 적절하다. 본문 확보 전 검색 결과 요약만으로 숙소 검증을 통과시키지 않는다.
