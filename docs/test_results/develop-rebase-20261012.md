통합 과정에서 검사 두 곳을 보완했다. 선택한 핀 앞뒤로 일정을 만드는 검사는 `strict` 모델 선택 경로와 `balanced` 직접 실행 경로를 모두 검증하도록 바꿨다. 실제 도구 1회 실행, 원문·선택 장소·대화 보존, 실행 후 재호출 차단을 확인한다. 프론트엔드는 팀에서 추가한 하이라이트를 포함한 16개 표시 메뉴의 ID·아이콘·설명을 검사하도록 오래된 시험 목록을 갱신했다. 제품 동작을 테스트에 맞춰 되돌리지 않았다.

프론트엔드 최초 Docker 검사는 형제 경로 `backend`, `data`, `nginx` 누락으로 여섯 곳에서 파일을 못 읽었다. Windows 실행에는 테스트용 심볼릭 링크 권한 제한이 있었다. 최종 검사는 공용 경로를 읽기 전용으로 마운트한 일회용 Linux 프론트엔드 컨테이너에서 수행했다. 중간 실패도 로컬 로그에 보존했다.
