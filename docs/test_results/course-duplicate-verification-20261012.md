# 코스의 추가 해석·중복 검증 감소

2026-10-12 로컬 Docker에서 광주 코스 지연을 조사하고 수정했다. 작업 기준은 `feat/remove-sbiz-data`, 변경 전 HEAD는 `fecb46c`이며, 최신 `upstream/develop`은 기존에 반영한 `fc8f29d`와 같았다. 모델과 메뉴·평점·실내·영업시간 검증 기준, 근거리 캐시 우선 범위는 변경하지 않았다.

## 변경

- `자장면 먹고`, `짜장면을 먹고 싶어`, `돈카츠 먹은 다음에`처럼 지원 메뉴·업종과 명확한 긍정 행동만 있는 표현은 정해진 문법으로 해석한다. 메뉴 판매 여부는 여전히 실제 근거의 `match`가 필요하다. 부정·선택·수식 조건 및 카페에서 식사처럼 업종으로 입증할 수 없는 요구는 기존 LLM 경로를 유지한다.
- 내부·외부 방문이 섞인 코스도 출발지부터 방문 순서를 정하며 방문별로 검증한다. 구장 전체 후보에 대한 선행 검증을 반복하지 않는다. 내부 매장의 자리어때 출처·메뉴 제한과 방문별 허용 범위는 그대로 적용한다. 출발지 경로 생성이 실패하면 기존 전체 후보 필터를 거친 뒤 대체 경로로 진행한다.
- 실시간 반경 검색과 기존 후보에서 같은 매장이 중복되면 이름·좌표·매장 ID가 같은 후보를 한 번만 검증한다. 입력 순서와 검색 메뉴 힌트를 보존하며 다른 지점은 합치지 않는다. 기존 요청 내 검증 결과 재사용도 유지한다.

## 실제 재실행

입력은 `16일 경기 자장면 먹고 구장에서 간식 먹은 다음에 술 먹고 산책하고 싶어 . 코스짜줘`다. 모든 실행에서 저장된 동일 출발 핀, 광주, 2026-10-16 14:00 KIA–NC 가상 경기, 빈 대화 이력과 새 코스 조건을 사용했다.

측정 범위는 실제 공급자·모델을 호출하는 `agent.answer` 엔진이다. HTTP/SSE, 채팅 저장, 프런트엔드 렌더링은 포함하지 않으며 사용자 지도와 대화는 덮어쓰지 않았다. 변경 전 반복 실행은 별도 프로세스에서 보존한 HEAD 소스를 메모리에 불러 사용했으며 실행 중인 앱 파일은 되돌리지 않았다.

| --- | ---: | ---: | ---: | ---: | ---: |
| 변경 전 최초 진단 | 52.062초 | 5 | 1 | 2.353초 | 0 |
| 변경 후 1차, 후보 중복 병합 전 | 74.687초 | 3 | 0 | 0초 | 1 |
| 변경 후 2차, 후보 중복 병합 전 | 62.110초 | 2 | 0 | 0초 | 0 |
| 변경 전 소스 반복 실행 | 65.335초 | 6 | 1 | 2.052초 | 0 |

모델 호출은 계측한 `ChatOpenAI._generate` 횟수다. 임베딩, 별도 Responses 검색, 경로 API를 합친 전체 API 호출 수나 과금 수치가 아니다. 웹 검색 경로 진입은 `_search_once` 횟수이며 내부 검색 동작 횟수와 구분한다.

**고정 캐시 상태의 A/B 시험이 아니다.** 기존 캐시를 유지했고 실행 중 근거 갱신과 외부 응답 시간, 모델의 해석 결과가 달라질 수 있다. 최종 23.757초를 코드만으로 인한 단축률이나 항상 30초 이내라는 보장으로 사용하면 안 된다. 변경 후 1차는 추가 메뉴 URL 검색이 21.781초 걸렸다. 2차는 평점·실내 후보 검증에 합계 약 24.7초가 걸렸고 최종 실행에서는 해당 검증이 짧아졌다. 외부 원문 조사 시간의 편차는 여전히 남는다.

구조적으로 제거된 처리는 명확한 메뉴의 추가 해석, 이미 메뉴 근거가 확인된 후보의 추가 모델 선택, 내부 간식 때문에 실행되던 전체 후보 선행 검증, 같은 지점의 중복 검증이다. 요청 전체 의도 해석과 실제 메뉴 원문 판정은 유지한다.

## 회귀 검증

`python manage.py test llm.tests --pattern='test_course*.py' --keepdb --noinput`

- 503개 중 501개 통과, 2개 실패. 실패 2개는 변경 전 소스에서도 그대로 재현한 기존 시그니처 데이터 불일치다. 저장된 광주 메뉴에서 `칠리치즈 핫도그`를 기대하는 `test_reference_dishes_need_actual_branch_menu_evidence`, `test_other_matched_dishes_can_be_selected_with_source_and_reference_links`가 실패했다. 이번 속도 수정에서 메뉴 자료를 추가하거나 기대값을 낮추지 않았다.
- 새 회귀: 긍정 행동 정규화, 부정·선택 조건의 의미 보존, 실제 메뉴 근거 필수, 중복 후보 병합과 다른 지점 보존, 내부·외부 코스의 선행 검증 생략, 경로 실패 시 검증되지 않은 후보 차단.
- 기존 회귀: 가까운 미확인 후보보다 먼 캐시를 우선하지 않기, 출발지 변경, 휴무·영업시간, 메뉴·제외 조건, 내부 출처 제한, 시그니처, 수정·삭제와 시간표.
- 스트릿츄러스 테스트는 고정된 첫 지점 URL 대신 실제 선택된 수집 지점의 ID·메뉴·상세 위치 URL을 검증하도록 보완했다. 위치 기반 선택이 다른 지점을 고르더라도 해당 지점의 정확한 자료를 보여줘야 한다.
- `git diff --check` 통과. 로컬 백엔드 반영까지 수행했으며 커밋·Push·운영 배포는 수행하지 않았다.
