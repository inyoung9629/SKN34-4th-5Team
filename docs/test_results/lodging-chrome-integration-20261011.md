# 서버 Chrome 숙박 코스 통합 검증

2026-10-11, 숙박 원문 조회를 OpenAI 검색/JEV 브라우저 에이전트에서 결정적 Google Chrome 수집으로 변경했다. Windows 단건 수집, 로컬 Docker MCP 수집, 실제 코스 생성 도구, 실제 V2 채팅 HTTP 응답과 저장 메시지를 검증했다. 운영 서버 배포나 다양한 모바일 화면의 렌더링을 검증한 결과는 아니다.

## 검증한 흐름

`카카오 후보 → 서버 Chrome의 NOL 일반 검색 → 별도 프로필에서 상세 원문 수집 → 이름·주소 대조 → 기존 조건 해석 LLM·원문 근거 검사 → 경기와 숙박 코스 → 채팅 SSE·저장 메시지`

Chrome 수집은 Node 표준 라이브러리/CDP만 사용한다. OpenAI 웹 검색과 JEV 조작용 모델을 호출하지 않으며 실패해도 유료 검색으로 전환하지 않는다. 조건 추출·해석, 코스 생성, 채팅 모델과 임베딩 비용은 남는다. 본 검증에서는 전체 모델 비용을 계측하지 않았다.

## 원문과 조건 확인

| 실행 | 결과 | 시간 |
| --- | --- | ---: |
| Windows 글래드 강남 코엑스센터 원문 | 이름·주소 일치, 보이는 DOM 6,571자 | 20.844초 |
| Docker MCP 글래드 원문 | 서버 Chrome의 DOM 수집 성공 | 21.122초 |
| Windows 글래드 조건 검증 | 주차·피트니스 충족, 선택 조건인 조용함 후기 충족 | 31.281초 |
| Windows 호텔 리베라 청담 조건 검증 | 원문·평점 확보, 주차·피트니스 근거 문자열 검증 실패로 미확인 | 30.860초 |
| Windows 신라스테이 삼성 조건 검증 | 주차·피트니스 충족, 선택 조건인 조용함은 반대 후기 우세 | 31.734초 |

원문 수집 성공과 조건 충족은 서로 다른 판정이다. 리베라 건은 모델이 원문에 없는 접두 문구를 근거에 붙여 연속 원문 대조를 통과하지 못했다. 근거 검사 기준을 완화하지 않았다. 후기 조건은 실제 날짜와 짧은 원문을 대조하며 일부 후기만으로 전체 리뷰를 읽었다고 주장하지 않는다.

## 실제 코스 생성

요청: “2026년 10월 7일 잠실야구장에서 경기 관람 후 주차 가능한 호텔 한 곳에서 숙박하는 코스를 만들어줘. 경기 전 다른 장소는 넣지 말고, 경기 관람과 숙박만 포함해줘.”

현재 로컬 DB의 10월 9~12일 경기에는 구장 연결이 누락되어 있었다. 테스트는 구장이 연결된 기존 10월 7일 경기 데이터를 명시했다. 미래 일정 검증 결과로 해석하면 안 된다.

초기 실행은 가까운 모텔 네 곳을 조회하다가 조회 예산을 소모해 실패했다. 카카오의 업종 분류로 요청 유형에 맞는 후보를 먼저 조사하도록 수정했다. 최종 유형 판정은 NOL 분류로 유지하며 이름에 ‘호텔’이 있다는 이유로 호텔로 취급하지 않는다. 다음 실행에서 숙박이 경기 전에 배치되는 오류가 드러나, ‘경기 전 다른 장소는 넣지 말고’라는 부정 문장이 뒤의 숙박 요약에 시점을 부여하지 않도록 수정했다.

수정 후 실행 중인 Compose 백엔드의 실제 `plan_course` 결과:

| 항목 | 결과 |
| --- | --- |
| 전체 도구 실행 | 29.826초 |
| Chrome 수집 | 글래드 강남 코엑스센터, 20.788초 |
| 경기 | 18:10 잠실야구장 입장, 18:30 시작, 21:40 종료 예상 |
| 숙박 | 22:03 글래드 강남 코엑스센터 도착, `AFTER` |
| 링크 | `https://nol.yanolja.com/stay/domestic/3012015` |
| 구조 | 경기 1곳·숙박 1곳, 좌표·시각·NOL 링크·`coursePayload` 생성 |

실제 카카오·Chrome·조건 모델·DB·Qdrant를 사용했다. 이 도구 실행에서는 OpenAI 네이티브 검색 함수와 JEV browse 함수가 호출되면 예외를 내도록 감시하여 두 경로에 의존하지 않음을 확인했다.

## 실제 채팅 API

새 테스트용 게스트 세션으로 `POST /api/v2/chat/sessions/` 201, `POST /messages/` 200/SSE `done`, `GET /messages/` 200을 확인했다. 전체 응답 시간은 **91.109초**였다. 모델 판단·후속 후보 조회·최종 답변이 포함되므로 단일 숙소 수집 시간과 구분한다.

- 최종 코스: 잠실야구장 → 22:03 파크 하얏트 서울 숙박
- 숙소 URL: `https://nol.yanolja.com/stay/domestic/10066533`
- 경기 다음에 `AFTER` 숙박 1곳, 지도 좌표·시각·`coursePayload`·완료된 작성 상태를 포함했다.
- 저장 메시지를 다시 조회했을 때 SSE 완료 응답과 같은 코스 및 최종 답변을 반환했다.
- 최종 채팅 문구는 주차 조건을 미확인으로 안내했다. 이 실행을 ‘주차 조건까지 충족한 응답’으로 계산하지 않는다. 조건 해석과 최종 안내의 일관성은 추가 개선 여지가 있다.

## 회귀와 실행 환경

- 숙박·브라우저·방문 가능 여부·첨부 위임 회귀 108개 통과
- 시점 해석·요청 활동·방문 조건·기본 출발지·코스 출력 회귀 53개 통과
- Linux MCP 수명주기·새 Chrome 도구·추적 회귀 11개 통과
- 실제 MCP 무인증/오인증 차단·정상 인증·출력 초과 정리 검사 통과
- 비루트 샌드박스 Chromium 다운로드 정리: 성공·시간 초과·취소 3가지 통과
- 백엔드와 브라우저 이미지 빌드 성공. Windows CRLF 체크아웃에서도 helper 패치와 entrypoint가 동작하도록 처리했다.

Qdrant가 없던 로컬 환경은 인증 키를 비공개로 설정하고 기존 벡터 4건을 백업 후 복사했다. PostgreSQL 원본은 보존했다. 기존 local Compose 설정을 유지해 백엔드를 재시작했다. 실제 `.env`, 브라우저 프로필, 원문 로그는 Git에 포함하지 않는다.

브라우저는 서버에서 실행하므로 사용자 PC나 모바일에 Chrome 설치가 필요하지 않다. 동명 숙소·NOL과 카카오의 상호 차이·사이트 변경으로 인한 검색 실패와 동시 요청의 `busy` 처리, 운영 부하는 별도 검증이 필요하다. 가격·재고·예약 가능 여부는 수집·판정 대상에서 제외한다.

재현 스크립트와 원본 결과는 Git 제외 경로 `backend/artifacts/lodging-comparison-20261011/`의 `integration_smoke.py`, `live_course.py`, `live_chat.py`, `live-course-result.json`, `live-chat-result.json`에 있다. 기존 3종 비교는 [별도 보고서](lodging-search-comparison-20261011.md)에 보존한다.
