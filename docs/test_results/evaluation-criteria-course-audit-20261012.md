# 평가 기준과 코스 생성·수정 흐름 점검

아래 1~3절은 수정 전 점검 기록이다. 사용자 승인 후 세 항목을 수정했으며, 변경 범위와 재검증 결과는 마지막 **후속 수정** 절에 기록한다.

## 범위와 판단

사용자가 `backend/llm/v2/evaluation/EVALUATION_CRITERIA.md`를 앞으로 참고하고 코스 변경 오류·지연 가능성을 확인하도록 요청했다. 기준 문서를 읽고 AGENTS 및 코스 성능 지침에 연결했다. 이번 점검에서 운영 코드·모델 설정·평가 원문은 변경하지 않았다.

기준 HEAD는 `6ac1bf5`, 이번에 다시 fetch한 팀 develop은 `718b99c`다. 이전 턴의 미커밋 선택 답변·URL 개선을 포함한 상태를 검사했다. 관련 파일 8개의 SHA-256은 Git 제외 경로의 스냅샷에 보존했다.

이 기준 Markdown이나 DeepEval 평가기가 일반 채팅 요청에서 실행되는 연결은 발견되지 않았다. 문서 자체 때문에 추가 모델 호출이나 코스 대기가 생기는 구조는 아니다. 충분한 근거 후 종료, 중복 조회 방지, 독립 작업 병렬 실행은 기존 성능 개선 방향과 일치한다. RAG 제외는 해당 평가의 범위이며 운영 검색을 제거하라는 요구가 아니다. 문서는 전체 요청의 새 시간 상한도 채택하지 않았다.

## 1. 선택 질문의 문구가 바뀌면 빠른 수정 경로를 놓침

관련 코드: `backend/llm/v1/rag/course/literal_edits.py:35`, `backend/llm/v1/rag/course/editing.py:497`.

이전 턴의 개선은 실제로 관측한 “돈카츠 가게로 바꿀 식당을 골라 주세요.: 1번 STATION”을 처리한다. 그러나 질문 생성 모델이 같은 의미를 다른 문장으로 쓰면 `CHOICE_QUESTION`에 맞지 않는다. 선택지의 장소는 같아도 문구에 의존해 다시 의미 해석·근거 검증으로 넘어간다.

원 요청, 현재 코스, 선택 대상 및 돈까스 전문 업종 후보를 동일하게 둔 오프라인 제어 흐름 검사:

| 선택 질문 | 단순 해석 | 추가 해석 경로 | 근거 검증 경로 | 후보 선택 |
| --- | --- | ---: | ---: | --- |
| 돈카츠 가게로 바꿀 식당을 골라 주세요. | 사용 | 0회 | 0회 | 성공 |
| 돈카츠 가게로 변경할 식당을 골라 주세요. | 미사용 | 1회 | 1회 | 근거가 없으면 실패 |
| 어느 식당을 돈카츠로 바꿀까요? | 미사용 | 1회 | 1회 | 근거가 없으면 실패 |

의미 해석 모델은 동일한 올바른 편집 계획을 반환하도록 대체했고, 추가 근거는 없는 조건으로 고정했다. 실제 모델 품질·응답 시간이나 문구별 운영 실패율을 측정한 것은 아니다. 모델이 대상을 정확히 해석해도 선택 답변 전달 방식 때문에 추가 호출이 생기는 경로를 확인한 것이다.

권장 조치: 확인 질문의 서버 상태에 원 요청·대상 방문 ID의 연결을 보존하고 그 연결을 검증해 재개한다. 단순 문자열 변형을 계속 정규식에 추가하는 방식은 일반 해결책으로 삼지 않는다. 추가 조건·직접 입력·오래된 선택의 검증은 유지해야 한다.

## 2. 신규 출처 검색 차단이 이미 확보한 일부 근거까지 버림

관련 코드: `backend/llm/v1/rag/course/evidence_memory.py:321`, `:351`, `:664`; `backend/llm/v2/agent/browser_research.py:271`.

V2 도구는 신규 출처 검색을 금지한다. 이 정책은 기준 문서와 일치한다. 하지만 코스 근거 검색은 기존 상세 페이지에서 일부 후보의 메뉴를 확인한 뒤, 나머지 후보까지 채우려고 `_search_once`로 넘어간다. 이때 정책상 `ToolException`이 발생하면 이미 확인한 `direct` 결과까지 반환하지 못한다. 호출자는 이를 빈 근거·API 오류로 처리한다.

기존 상세 페이지 읽기는 성공하도록 대체하고 실제 신규 검색 금지 경계를 사용한 오프라인 검사:

| 후보 수 | 이미 확인한 후보 | 결과 |
| ---: | ---: | --- |
| 1 | 1 | 확인 결과 1개 반환 |
| 2 | 1 | `ToolException`, 확인 결과 반환 0개 |

이는 실제 웹사이트 조사 결과가 아닌 제어 흐름 재현이다. 추가 모델·외부 네트워크를 호출하지 않았다. 코드상 확인 가능한 문제는 “검색 금지”와 “페이지/제공자 실패”를 구분하지 못하며 부분 성공을 보존하지 않는 점이다. 상세 조건·메뉴 근거가 필요한 수정에서 정상 후보를 누락시키거나 다음 턴의 재시도를 유발할 수 있다. 금지 예외 자체는 즉시 발생하므로 그 예외가 수십 초 대기한다는 뜻은 아니다. 그 전에 수행한 원문 읽기·검증 비용이 낭비될 수 있다.

권장 조치: 신규 검색이 허용되지 않는 요청에서는 기존 URL 확인 결과를 보존해서 반환한다. 미확인 후보는 미확인으로 두고, 실제 충족 근거가 있는 후보만 선택한다. 신규 검색을 다시 켜거나 모든 조건을 무시하는 해결은 하지 않는다.

## 3. 10월 16일 가상 경기의 표식 누락

관련 코드: `backend/llm/v1/rag/course/agent.py:282`, `backend/llm/v1/rag/course/editing.py:659`, `backend/llm/v2/agent/course_output.py:83`.

로컬 일정의 읽기 전용 검사에서 광주 14:00 KIA–NC, 잠실 17:00 두산–롯데는 모두 `source=demo`, `game_type=DEMO`, `source_status_label=가상 경기`다. 일정 도구도 해당 필드를 반환한다. 하지만 코스의 `find_game`이 필요한 필드를 재구성하면서 이 표식과 실제 수집 시각을 버리고, 공개 `game`에는 날짜·시각만 남긴다.

이전 턴에 실제 API로 실행한 광주 수정 성공 결과(6.213초)를 다시 확인했다. 답변은 666자이며 기준 경기로 10월 16일 14:00을 안내하지만 가상·시연 표시가 없다. 이번에 새 유료 코스를 생성하거나 사용자 대화를 수정하지 않았다. 해당 출력은 표식 누락의 실제 근거다. 잠실은 이번 점검에서 도구 → 코스 변환의 누락까지 확인했으며 새 최종 답변을 생성하지 않았다.

기준 문서는 가상 경기를 실제 일정처럼 안내하는 것을 중대한 실패 ⑤로 규정한다. 따라서 이전의 “코스 교체 성공”은 장소·시간표 변경 기능의 성공이며 이 평가 기준 전체를 통과했다는 뜻이 아니다. 새 DeepEval 전체 평가를 수행한 것은 아니다.

권장 조치: 일정 출처·가상 여부를 해석, 재계산, 저장, 공개 결과까지 전달하고 최종 답변에서 가상 표시를 유지한다. 추가 모델 검증이 아닌 데이터 전달·표시 수정으로 처리할 수 있다. 정상 TVING 일정의 출처·수집 시각 보존도 같은 경로에서 별도 검사해야 한다.

## 문서·평가의 정리 필요 사항

- 평가 기준 상단은 비공격 불명확 요청의 가드 PASS를 확정했지만 본문 일부는 아직 “라벨 보류”라고 적혀 있다(예: 112행, 조건 변경 표). 현재 정책 상태표와 명시된 확정 절을 기준으로 읽고 오래된 표현을 정리할 필요가 있다. 문구 불일치 자체가 현재 런타임 지연을 만든 증거는 없다.
- 기존 `test_native_url_policy.py`는 URL을 읽을 때 OpenAI 네이티브 `web_search`를 강제하던 예전 미들웨어를 기대한다. 현재의 본문 읽기 전용 정책과 맞지 않는다. 이 검사를 통과시키려고 웹검색을 되살리면 정책·비용·지연이 다시 바뀔 수 있다. URL 검증 자체의 필요성과 어느 계층에서 검사하는지는 구분해야 한다.

## 후속 수정 — 2026-10-12

팀 develop을 다시 확인했으며 `718b99c` 이후 변경은 없었다. HEAD `6ac1bf5`의 진행 중인 변경을 보존한 상태에서 수정했다. 커밋·푸시·병합은 수행하지 않았다.

### 변경과 영향 범위

1. 단순 교체의 대상만 모호할 때 서버 코스 기억에 원 요청 전체, 가능한 방문 ID, 현재 코스 스냅샷을 저장한다. 완료된 턴의 실제 선택 UI를 다음 코스 도구에 메타데이터로 전달해 질문 문구와 관계없이 선택을 연결한다. 날짜·방문·순서가 달라졌거나 조건이 추가된 답변은 빠른 경로로 추측하지 않는다. 성공 후 대기 상태를 지운다. 복잡한 원 요청, 알레르기·주차 등의 추가 요구는 기존 의미 해석을 유지한다.
2. 신규 출처 검색이 금지된 코스에서는 기존 페이지로 확인한 부분 근거를 반환한다. 미확인 장소나 제외 조건을 통과시키지 않는다. 같은 후보를 새 출처 없이 반복 검사하지 않으며 정책상 미확인을 제공자 장애로 기록하지 않는다. 실제 취소는 취소로 전파한다. 신규 검색 허용 경로의 기존 동작은 유지한다.
3. 일정의 `source`·`game_type`·`source_status_label`을 코스의 경기 선택에 보존하고, 가상 여부를 공개 코스와 서버 기억에 전달한다. 생성·재계산·저장용 결과 및 코스 직접 답변에는 **시연용 가상 경기** 안내를 붙인다. 브라우저에서 들어온 가상 표시는 신뢰하지 않으며 동일 구장·날짜·시각의 서버 기억에서만 복원한다. 실제 경기의 출력과 20분 전 도착 계산은 유지한다.

공통 가드, capability 매핑, 역할별 도구 권한, 모델·추론 설정, 일반 웹 읽기 정책은 바꾸지 않았다. 선택 메타데이터를 사용하는 곳은 `plan_course`뿐이며 다른 이관 도구에는 기존 형식의 대화만 전달한다. 메타데이터 추가로 모델에 보내는 질문·답변 본문이 늘어나지 않는다. 실제·가상 경기의 판정도 코스 소비 경로에서만 변경했다. 이 범위와 회귀 검사는 다른 챗봇에 대한 영향 가능성을 줄이는 근거이지 모든 실제 입력에 대한 무영향 보장은 아니다.
